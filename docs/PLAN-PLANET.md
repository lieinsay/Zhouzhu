## 一、要解决什么

现在游戏里只有一个岛群（2051，84 × 101 km），摆在一张平的地图上；换地图是整场景切换。生成器那边是一整颗行星：半径 6371 km、8000 个岛群、陆地 2500 万 km²，任何一个岛群都能按需生成细节（第三层）。

用户的目标：**生成器负责给地图数据，游戏负责实时生成，能渲染整个行星。** 落到能验收的样子：

1. 在任何一个岛群里，地平线是弯的，远处邻群的山从地平线上冒出来；
2. 从村口一路升到轨道，看到整颗星——云海、岛群、风带与永暴、昼夜分界、夜里村落的灯——再落回村口，全程不闪不跳；
3. 开船从一个岛群飞到另一个，落地，那边的村子有人，有它自己的时令、天气和地方时；
4. 8000 个岛群的任何一个都能去：开发机上先靠生成器现生成，最后移植进游戏、不要 Python；
5. 原有的一切照常：2051 的全部玩法、平板岛与甲乙两岛两张小图、全部 e2e。

不在本计划内：全行星的社会模拟（2.5 亿人不逐人算）、存档（离开的岛群的账先留在内存里）、行星级玩法（贸易航线、邦国外交）、生成器十步管线本身的改动。

几个结构性的事实（每一期都绕不开）：

- **生成器的岛群是在一张抽象平面上出的**：群心 = 主岛质心 = 节点经纬度，x 东 y 北（km），没有任何投影；气候、风只在群心取一次。放上球面要游戏自己定投影（D6）。
- **高度 0 = 云带顶，全行星同一个面**；岛底在云带顶以上 ≤ 300 m（台面低的岛更薄）。云带顶离海面多高、云带多厚，生成器没定义。游戏把看得见的云海放在 −3800 m，露出悬空的岛底。
- **邻群的陆地常常叠在一起**：生成器从不查群与群之间的碰撞。本次实测：把 1 km 粗版按 AEQD 放上球面，比每群与最近的 6 个邻群——
  - 密接群（全部 251 个）：41% 的邻群对陆地相距不到 2 km，很多是直接压在一起；
  - 中疏群（抽 300 个）：13% 的邻群对陆地相距不到 2 km。
  - 2051 和它的近邻 2050、2049、1827 都离得远，碰不上。
- **生成器的行星坐标**（`sphere.py`）：经度东正；单位向量 x 指 (0°N, 0°E)、y 指 (0°N, 90°E)、z 指北极；1° 网格格心对齐、第 0 行在南。气候场都是年均，季节变化只在各群的气候里（带界随太阳摆动）。
- **游戏处处假设一张平图**：
  - 没有浮动原点，godot-cpp 是单精度；
  - 太阳没有经度：`weather.tsv` 头里有 lon，但没人读，一张图一个时区；
  - `Hinterland` 给整张图的每个村开账，从不释放；
  - 地面块、散布块、河块的键是 24 / 28 位（约 2,100 km）；
  - 相机远平面 60 km；云海是 240 km 见方、y = −3800 的平板；天上的云层是 y = 2800 的平面；
  - 雾顶、海拔表（全局着色器参数）一张图一份；
  - 换地图是 `change_scene_to_file`，整场景释放。
- **平板岛、甲乙两岛是一等公民**：`main.tscn` 是启动场景，7 条 e2e 跑在它上面，3 条在平板岛上。行星的东西必须是可选的：没有行星数据的地图一切照旧。

## 四、总体设计

### 4.1 分工与数据流

```
skyisle-gen（Python，离线 / 开发机）                          Zhouzhu（Godot 4.4 + C++）

十步管线 ①–⑨（全行星，2 分钟） ─┐
                                ├─ tools/export_planet.py ─▶ 行星包 planet.bin（岛群表、1° 风与气候、板块、带界、人口）
第三层粗版 island lod（每群 < 0.5 s）┘                         粗版包 lods.bin（全行星 1 km；2051 周围 600 km 500 m）
第三层细版 island <节点>（每群 5–40 s）
        └─ tools/export_skyisle.py（1 s）─▶ 岛群包 worlds/<节点>/（五份文件）或 user:// 缓存

游戏：PlanetData（纯 C++ 读行星包、粗版包）
  ├─ PlanetView：相机的经纬度、局部系、弯曲参数（P1）
  ├─ FarGroups / PlanetGlobe / 大气 / 行星云：600 km 外到轨道（P1、P2）
  └─ GroupStream：按距离给岛群分档、载入 / 卸载、换锚（P3）
       └─ GroupWorld（今天的 World，一群一个）→ 地面、河、散布、村子、账房……（现状）
       └─ GroupProvider：仓库里的包 → user:// 缓存 → 调生成器（P4）→ 游戏内 C++ 生成（P6）
```

### 4.2 坐标系

- **行星系 P**（双精度，只在 CPU 上）：原点星心，轴与生成器 `sphere.py` 相同；基准球半径 R = 6,371,000 m = 云带顶。
- **岛群平面系 G_k**（就是今天的游戏坐标）：x 东、z 南、y = 云带顶以上的米，原点 = 节点经纬度在基准球上的点。生成器的 km（x 东、y 北）→ 游戏 (x·1000, −y·1000)，与今天一样。
- **平面 → 球面 T_k**：方位等距（D6）。平面上离群心 s、方位 α 的点，映到球面上离群心大圆距离 s、方位 α 的点，高度沿径向。
  - 在群心切平面上写成 T_k(p) = p + δ(p)：竖直方向降 |p_h|²/(2R)，水平方向缩 p_h·|p_h|²/(6R²)。
  - 精确式与误差界在 P0 定下并单测；100 km 处降 785 m。
- **锚**：同一时刻，物理和 Godot 节点坐标都在一个岛群（锚）的平面系里。
- **画面弯曲**：所有顶点走同一个着色器 include `planet_curve.gdshaderinc`：

  ```
  visual(p) = c + R_cᵀ · ((p − c) + (δ(p) − δ(c)))
  ```

  - c 是相机的平面坐标，R_c 是相机所在处球面的局部系（用锚平面系表示）。
  - 近处 visual(p) ≈ p，物理与画面一致；远处按真球面下弯。
  - R_c、c、δ(c) 每帧由 CPU 用双精度算好，作为全局着色器参数传进去。式子里全是相对相机的小量，单精度够用：锚群内 ±100 km 误差 ≤ 2 cm，与今天的单精度坐标本身同一量级（100 km 处 float 只准到 8 mm）。
- **非锚的岛群**（远处的低模、P3 载入的邻群）：顶点在它自己的平面系里。
  - 群心相对相机的位置与朝向：相机动了才由 CPU 用双精度算，作为这一群材质的刚体部分传进去。
  - 群内的 δ_j 在着色器里按它自己的群心算。
- **换锚**：人或船离哪个群的陆地最近，就以哪个群为锚（回滞 2 km）。
  - 换的时候，人、船、相机和正在动的物体的位置、朝向、速度都从 G_a 经球面换到 G_b。两个群心之间的夹角 = 群心距 / R，岛群之间是 0.1°–3°。
  - 旧锚的地面改成非锚画法、撤掉碰撞；新锚的地面归位、挂上碰撞。
  - 换锚只在云海上空发生。画面只取决于真球面位置和相机，所以换锚时画面不跳。
- **剔除**：顶点下弯之后，引擎仍按平面的包围盒剔除。远处的块要按弯过的位置给包围盒，或者放大 `extra_cull_margin`，否则地平线附近的东西会被错剪。

### 4.3 远近分层

| 离相机 | 画什么 | 数据 | 哪一期 |
|---|---|---|---|
| 0–6 km | 现有全部：2 m 地面、树、村子、河、资源点、村民 | 岛群包 + 实时细化 | 现状 |
| 6–60 km | 所在岛群的粗地面块、远处林子 | 同上 | 现状（P1 起弯曲） |
| 60–600 km | 邻近岛群低模：500 m / 1 km 粗版网格，地表着色、季相、积雪、岛底剪影 | 粗版包 | P1 |
| 600 km 到轨道 | 行星球（云海面）+ 行星贴图（岛群烘进立方体贴图）+ 大气 + 行星云层 + 夜侧村落灯 | 行星包、粗版包 | P2 |

邻群低模为什么要画到 600 km：站在云海以上 2 km，地平线在 160 km 外；两座 2 km 高的山相距约 320 km 还能互相看见。

### 4.4 流式、线程与内存

- **共用一个任务池**：从 `World` 里提出来（P3）。所有岛群、远景、行星贴图的后台活都进这一个池，按离相机的米数排先后。
- **岛群分三档**：
  - 远景：只有粗版网格；
  - 近景：地面块 + 远处林子，没有碰撞；
  - 细版：全部内容，是锚或即将成为锚。

  同时处于细版的岛群 ≤ 2 个。
- **`World.load` 挪到后台**：现在是同步的，Debug 下约 1 s。载入期间用远景顶着。
- **预算**（Debug、窗口）：
  - 地面上行走，帧时比现在多 ≤ 2 ms；
  - 跨群飞行，最慢帧 ≤ 50 ms；
  - 轨道视角，帧时 ≤ 16 ms；
  - 进程内存 ≤ 1.5 GB。

### 4.5 时间、日月、天气

- **日月**：按相机所在的经纬度算（AEQD 逆算）。行星系里只有一个太阳，换算到相机的局部系后给光照和天空用。
- **钟**：按 D10。村子出工收工按各自经度的地方时：`LocalSeason` 加上经度。
- **天气**：
  - 每个岛群一个 `WeatherModel`，读它自己的 `weather.tsv`。
  - 相机处的天气在群与群之间按到各群陆地的距离加权过渡，过渡带约 20 km。
  - 全局着色器参数（海拔表、雾顶、半球号）改成每群一份：用材质参数，或按群号查的纹理数组。全局的只留相机处的。
- **行星云层**（P2 起画，P5 与地面对上）：
  - 远处和轨道上看到的云，由 ④ 的气候场、各群当天的天气、顺风平移的噪声三者合成；
  - 100 km 以内交给岛群自己的云团模型；
  - 季节靠带界随太阳摆动（生成器第三层气候的同一式）。

### 4.6 模拟分级

- 细版岛群：`Hinterland` + `SiteStream` 照旧，每群一份。
- 卸载时，账本存成文本留在内存（`save_village_state`）；回来时 `load_village_state` 读回再补结。离开超过 1 个游戏日的，只补最后 1 日，其余视为按汇总过了。先这样，等做存档时再细化。
- 其余岛群：只有生成器 ⑨ 的人口和邦，在地图上、HUD 里读。

### 4.7 按需生成的缓存键

- 缓存目录是 `user://planet/seed42/groups/<节点>/`，里面有一个 `stamp.json`，记着：
  - 生成器提交号；
  - run 的 `config.resolved.toml` 哈希；
  - `[island]` 段哈希；
  - 导出版本（`terrain.bin` 版本 + 导出脚本哈希）。
- 任一项对不上就重新生成。

### P0　行星数据与坐标地基

- **前提**：无。
- **目标**：游戏手里有整颗行星的数据和一套验证过的坐标数学，邻群不再叠在一起。这一期不画东西。

**生成器（skyisle-gen）要做的**
1. **邻群不重叠**（D12）：第三层布局加「势力范围」约束。
   - 取节点的球面 Voronoi 单元（邻居取自 s03），用 AEQD 投到该群平面上，再往里收 `gap_km`（默认 3 km）。
   - `place_islands` 拒绝越界的摆放，不裁岛形。
   - 光拒绝可能摆不下：密接群的势力范围半径只有 30 多 km，布局的岸距却按 1–15 km 撒。碰到约束的群要允许按势力范围大小收紧群内间距；只对这些群收紧。
   - 新增 IS-terr（硬项）：群的陆地不出界。
   - 没碰到约束的群，产物哈希不变（2051、2050 属于这种，要验）。
2. **粗版批量**：新命令 `skyisle island lod --run out/seed42 --res 1000 [--nodes …|--near 节点 --radius km] [--jobs N]`。
   - 只跑布局 + 地形，再加地表分类必需的最少步骤。
   - 写 `out/seed42/islands_lod/<res>/<节点>.npz`（height、island_id、landcover、raster 头）和 `index.json`；多进程。
   - 粗到小岛比一格还小时不能崩：修 `shoreline_gaps` 的空数组；小岛至少占一格，或者该群自动退到细一档。

   - 都没有就调生成器：后台进程先跑 `python -m skyisle_gen.cli island <节点> --run <run> --export <临时目录>`，再跑 `tools/export_skyisle.py`，读进度、出错时报错。
   - 生成器的路径放在项目设置里（`zhouzhu/generator/python`、`root`、`run`），默认值取开发机的路径；进程带 `PYTHONUTF8=1`。
2. **缓存键**：按 4.7，对不上就重新生成。
3. **预取**：船头方向 150 km 内的群先生成，同时最多 1 个生成进程。
4. **行星地图**：
   - 一个地球仪面板，8000 个群按类、气候或邦着色；
   - 悬停读数：节点号、陆地、经纬度、邦、人口、有没有缓存；
   - 点一下就开发者瞬移，等生成时有进度；也能设为航向；
   - F2 的列表里加「行星」。
5. **落点**：该群的主码头；没有码头就落在邑治。
6. **e2e `planet_jump_e2e`**：
   - 挑 3 个群：一个已缓存、一个没生成过、一个高纬；
   - 依次瞬移、落地，检查地面就绪、村子挂上、纬度与季节对；
   - 没有 Python 时报 SKIP，不算 PASS。

**验收**
- 没生成过的群，从点下去到能走 ≤ 60 s，期间不卡帧（最慢帧 ≤ 50 ms）。
- 已缓存的群 ≤ 5 s。
- 随机 5 个群都能落地成功，要含极地、赤道带边、密接群。

### P5　全球天气与风

- **前提**：P2、P3。
- **目标**：天上看到的云和地上下的雨对得上；锋面从一个群扫到下一个群；风带真的推船。

**做什么**
0. **全部 8000 群的逐日天气**：没生成过细版的群没有 `weather.tsv`。
   - 生成器的气候步骤很便宜（全行星 4 s），天气步骤只差岸缘高 `rim_m`，这个值由粗版给。
   - 让 `island lod` 顺带出每群一年的逐日天气，由 `export_planet.py` 打进行星包，按 8000 × 336 天 × 6 字节压缩，约 5–8 MB。
   - 有细版的群以细版的 `weather.tsv` 为准；报一下粗细两版天气类型逐日相同的比例，应 ≥ 95%。
1. **行星天气场**（纯 C++）：
   - 以各群当天的天气为真值，即它自己的逐日表加上锋面到达时刻；
   - 群与群之间按距离和风向插值，再叠上顺风平移的天气尺度噪声；
   - 能给出任意经纬度、任意时刻的云量、降水和风。
2. **行星云层**（P2 做的）改读这个场；100 km 内与岛群的云团一致：同一个场在近处退化成云团模型。
3. **群间的风**：② 的 1° 风场加上当天的扰动；在开阔云海上，船按它漂（沿用现在的 `wind_drift`）；赤道永暴带和 G 圈里有风暴、禁航。
4. **体检 `--planet-weather`**：一年里全行星的云量、降水统计，与 ④ 的气候场对账，误差 ±20%。

**验收**
- 从轨道上看，某群上空的云与它当天的天气类型一致：晴天没有云团，雨天有。
- 在两群之间飞一趟，天气逐渐过渡，没有瞬变。
- 船在风带里的漂向与 ② 的风一致。
- 体检对账达标。

**规模**：中。

**提示词**
