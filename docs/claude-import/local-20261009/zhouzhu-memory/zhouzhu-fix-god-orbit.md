用户报「god 飞到很高、绕着行星转、再落地场景乱了」。子任务复现出四处叠加：锚只在陆地 30 km 内换、高空永远是 2051（一圈后平面坐标 40,069 km，超过对跖点 20,036 km）；
FarGroups 低模每帧重复交后台、一圈内存 319 MB → 12.2 GB；地面块碰撞段积到 7,942 段排序吃满帧时、落脚处挂不上；生成队列先来先做、停下的那群前面排着十几个飞过的群。
修（Zhouzhu 47cf460、ed5693b、9f6ea11、7138193、87f7a88、0f219c8，2026-09-28 已推送 origin 与 mepro）：过对跖点换回半圈以内的同一点；离锚群陆地 > 150 km 且平飞 < 3 km/s 时换到最近的群（没生成就当场生成）；
低模不重复交、走远就扔；旧块碰撞段丢掉、只挂最近一批；生成队列近的先做、1,000 km 外撤掉。新 e2e god_orbit_e2e（一圈落回主码头、飞 3,000 km 换锚到 #3405 落地、内存增长 ≤ 1 GB）。ctest 5/5、25 条 e2e 过。

**Why:** 没修掉的是架构问题：高空快速巡航时人仍在锚群平面里，离锚几千公里方向偏（1 万公里十几度），低于 60 km 又快又远时脚下云带顶与海面变形。
**How to apply:** 用户若要根治，两条路待拍板：高空用一个不挂岛群的空平面当锚、落地前再换真群；或 god 高空改用 F7 那样的双精度球面运动。见 [[zhouzhu-plan-planet]]。
