# 09 · 首版垂直切片

## 目标：验证一个问题

> **那些琐碎的文化细节，能不能在秩序更替时转化成情感重量？**

如果能，整个项目的核心就立住了，剩下都是扩展。
如果不能，现在推翻的成本最低。

**次要验证**：「同一件事在两个地方被读成两种意思」，玩家觉得有趣还是觉得烦？

## 范围

| 项 | 首版做 | 首版不做 |
|---|---|---|
| 地区 | **2 个邦**（母邦 + 一个邻邦），各填一份九格表 | 其余诸邦、其他大区 |
| 文化微差 | **4–5 条**，每条都做到位、都能被踩到 | 完整文化价值表 |
| 深度 NPC | **5 人**，其中 ≥2 人在兼并时立场分裂 | 婚恋、心事件全线 |
| 社交机制 | **人情账本 + 文化棱镜**做完整 | — |
| 关系网 | 最简版：2 组人物关联 | 完整关系图 |
| 风评传播 | 粗略版：按「是否去过该地」 | 航线密度模型、代言人 |
| 处境时间线 | 5 条，每个 NPC 一条 | — |
| 空艇 | 1 艘，载重升级 1–2 档 | 网格建造 |
| 定居点 | 1 个主家，农田 + 仓库 | 前哨、居民迁移 |
| 航行 | 1–2 条有价差的航线，顺逆风轻度差异 | 雇佣船长、商号 |
| 生态 | 每邦 1–2 种特有物产 | 完整生态 |
| 人种 | 2 套外观（对应 2 邦） | 多出身 |
| 兼并者 | 仅作为**压力源**存在，不可前往 | 国战、可去的领土 |
| **叙事** | **完整走通：日常 → 渗透 → 破城 → 载重取舍 → 新秩序的头三件事** | 完整第三幕、终局 |

### 第三幕在首版只做「头三件事」

不做完整的第三幕，只做三个最能说明问题的改制事件：

1. **官秤重校** —— 你的旧秤作废，要去排队换。方便了，但你爹留下的那杆秤没用了。
2. **文字统一** —— 你的契约要重立，你写的字成了讹字。
3. **历法统一** —— 两邦的灯会挤到了同一天。你终于不用两头跑，但也再没有理由去南边了。

**这三件事就足以让玩家尝到"便利与失去是同一件事"。**

**目标时长：4–6 小时。这个切片本身是一个完整的、有力量的小游戏。**

## 开发顺序

1. **纸面原型**（不写代码）
   填完两份九格表，手推一遍玩家路径：5 个 NPC、5 条微差、破城清单、三件改制。
   判断有没有「我想再玩一会」的时刻。
2. **数据先行**
   把人情账本、行为标签、文化偏移量、处境时间线定义成数据表（JSON / Godot 资源）。
   **这几张表是整个游戏的地基，比任何代码都重要。**
3. **可玩骨架**
   1 船 + 2 岛 + 移动 + 载重 + 买卖。无美术，色块即可。
4. **社交机制接入**
   账本记录 → 对白引用；行为标签 → 两邦不同解读。
   **此时应能第一次感受到「文化棱镜」的味道。**
5. **处境时间线**
   5 条，验证「世界不等你」。
6. **第二幕流程**
   渗透事件序列 → 破城 → 载重取舍界面。
7. **第三幕头三件事**
   官秤 / 文字 / 历法。**这是本切片真正要验证的东西。**
8. **打磨与外部试玩**
   重点观察两处：
   - 破城时玩家会不会犹豫。**犹豫＝成功。**
   - 三件改制之后，玩家有没有过一瞬间的失落。**有＝核心成立。**

## 显式推迟清单

前哨系统 · 雇佣船长 · 商号 · 船体网格建造 · 其他大区 · 多出身 · 婚恋 ·
节日轮转 · 居民迁移 · 完整第三幕 · 终局 · 抵抗/合作等多结局分支

> 架构上**留接口**（尤其是文化表的「主表 + 偏移量」结构、账本的事件数组），
> 但**先不实现**。本作结构极适合增量开发——加一个岛就是加一份内容，不用重构。

## 已知工程风险（首版就要处理）

1. **人情账本的存档体积** —— 事件数组持续增长，需要归并/压缩策略
2. **对白引用账本条目** —— 需要模板/插槽机制，让 NPC 自然说出「你上次说会再来的」
3. **处境时间线的调度** —— 游戏内日期驱动的事件队列，玩家不在场时也要推进
4. **文化表的合并规则** —— 主表 + 偏移量的覆写与继承
