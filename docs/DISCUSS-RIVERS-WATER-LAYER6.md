## 1. 主链与范围：玩家改变原因，同一份水作出响应

本次复核以用户明确的目的为准：**营造较为真实、能读懂且会延续变化的水陆环境，使修水利、治水有合理有趣的土壤。**守恒、几何与版本相容是支撑这一目的的条件；还要让玩家能从自然环境看出问题、选择办法、观察实际改善与代价。下列环境与取舍补充已随第六层获设计确认，不把它们写成已实现玩法。

推荐主链：**有位置、工具与工料约束的施工 → 实际材料移除/安放和工程开口变化 → 当前实体、层界、孔隙/通路及库容变化 → 原有水盐沙在真实空间内有限交换 → 上下游、地下及床岸共同响应 → 同版几何/水态/库存相容发布 → 保存和维护这一真实历史。**

生成器继续负责初始自然世界及成因，运行宿主负责玩家操作及当前物理状态的推进，使用前四层同源C++过程与物质账；不另建一套Python算法或“玩家水”供给公式。游戏不能为修复上游自然河宽深而补造几何；本层允许的变化是**具有施工和材料来源的真实改造**，不是借玩家接口重塑所有自然河。源河段标识可追溯，当前水路与断面不必永久锁定初始中心线。

本层覆盖浅表挖填、开沟、切口、堤埂/阻水、蓄塘、溢流/泄流、局部河槽变化、接触地下水、以及井/管道/泵以后接入所需的最小物理边界。设施技术与具体施工工法须符合世界已有能力；不默认木锹能在深水或完整硬岩中任意施工。详细物性、分辨率、工具工时、结构强度、数值求解与代码接口以后细化。

浮石仍为独立元素，金银不变；骨架深埋、当前科技无法挖到岛级核心/结构层的边界保留。有限高压固态岩层不是挖一格就触发的岩浆或供泉开关。不扩展毁岛、核心破坏或全球完整地动力学；局部岸体失稳与工程冲毁仍按第三层实际材料过程讨论。

生态环境与生物演化继续延期。饮用/灌溉/生产消耗、取水容器、游泳、浮力、航船吃水等由第七层独立讨论；本层提及井、泵和管道，只确定它们怎样引用已有水、通路与机械功，不因此在第六层设计完整玩家用水系统。

### 1.1 环境先成立，治水的理由从现场长出来

自然状态既有河槽，也有相连的岸地、低洼储水空间、地表径流路径、土层湿态与地下接触。不能只做一条可被编辑的蓝色水带，再给沿岸布置固定“待修水利点”。同一套地貌、层序、来水与泥沙条件，应自然产生水容易通过、容易滞留、容易渗入或受到控制的不同位置；玩家先理解现场，再决定是否改造。

真实不等于处处急流深水、到处洪灾或不断坏工程。干沟、近静水、季节性湿地和较稳定的岸地同样成立；一处在自然状态已经合宜，就可以不修。地点差异不按每岛任务配额制造，也不保证每个地方都能修出大水系；源输入不足或实际条件不适合时明确保留。是否改进世界生成，需要以后单独授权和同版证据，本轮不重塑现有岛屿。

### 1.2 六类自然差异，应能进入工程判断

下表是前几层已有过程在第六层的环境含义，不是新增地貌配方、事件频率或强制样板：

| 实际成因与条件 | 玩家需要辨认的现场差异 | 可产生的水利问题 |
| --- | --- | --- |
| 来水历程与有限地表/地下储留 | 当前有水、旱时可供与一次涨水不是同一件事；枯涨、退水与响应快慢有依据 | 是否需要留水、何时开闭已有控制口；不能按晴天的一次流量许诺全年供水 |
| 河谷/岸地高程、盆地低口及相连低地 | 主槽能排水，不代表低地也能排；低口与回水能控制淹水位置和持续过程 | 疏通控制口、留出行洪/临时储水空间，或保留原低地；不能见湿就只加深沟 |
| 全路高程、水头、接收空间和下游边界 | 相近两处可能隔埂，低渠也可能受下游顶托 | 引水、分流、排水的可行路径与受体承受条件；水移走后确有去处 |
| 真实层序、孔隙与地下接触 | 透水段、滞水段、侧向渗入和湿土有区别；湿土不都等于露天水面 | 渗漏、排湿、取水与有限防渗的取舍；不因材料名字给固定漏水率 |
| 有限泥沙来源、输运条件与床岸材料 | 有些口易积料、有些段易冲刷，有些较稳定；不是每段必然淤满或崩塌 | 选址、入口/出口组织、护持和清淤；不能以无来源淤泥制造重复劳动 |
| 岛体范围、浅部可施工材料与真实外排口 | 可用地面、储水空间、施工面和材料均有限；岛缘不自动接海平面排水 | 工程尺度、弃料与外排路径有边界；不靠无限深坑或空中接水域消除问题 |

这些差异需要生成器提供可核对的自然原因，导出包保留，运行水态继续响应，游戏按第五层表达。当前包是否已具有足够的差异和可读线索，仍待以后同版现场核验；本稿没有据原稿调查或动画宣布它们已经齐备。

### 1.3 有意义的选择，来自不同目标之间的取舍

本层先评价水陆环境的实际改善，例如目标位置的水位/积水历程、湿态、可通水路径、可用蓄排空间和床岸稳定趋势，不预定第七层的作物收益、饮水需求或奖励经济。

| 意图 | 条件成立时可考虑的方向 | 必须同时看见的代价或边界 |
| --- | --- | --- |
| 引到所需位置、疏通或排走水 | 利用适宜坡降与控制口，分段开沟、疏通或调整出口 | 有限来水被分配、沿程损失与水沙到达；受体水位和可承接空间，不把风险移到镜头外 |
| 在适宜处留水 | 利用真实低地与有限拦蓄、保留控制出口 | 占地、上游水位与湿态、渗漏/蒸发及原下游来水的改变；满库前的余量与已经存水分开 |
| 应对涨水、降低某处受淹 | 保留/调整相容分流、行洪路径或临时蓄滞空间，必要处局部防护 | 改变的是洪水经过的位置和历程；加快排出可能把负担传给下游，不能只看本地最高水位 |
| 减少冲刷、淤堵或日常工量 | 先选适合的线路和断面，再按条件采取护持、留沉积空间、清理或控制开口 | 材料、施工、输沙去向和后续工作；既不默认一劳永逸，也不强制所有工程反复损坏 |
| 暂缓、改址或保留自然空间 | 观察、缩小目标、让出不适宜改造的位置 | 放弃一部分预期作用可能比持续加堤挖深更合理；不施工也是有效选择 |

没有一种“挖更深、筑更高、接更多支路”在所有地点都更好。是否存在多种可行做法由现场决定，不强迫每处都有等价答案，也不设计成猜唯一隐藏阈值的水利谜题。空间和时间上的外部影响需要能追溯；有依据的小工程也应能带来可识别、能保持一段实际历程的改善，不把有趣等同于灾害频率、维护次数或惩罚强度。

## 3. 一套当前物理状态，四类责任

自然源包是起点与来源记录，不是每次施工后重生成的世界。当前实体由自然变形/冲淤和玩家实际材料操作共同演化；工程历史记“做过什么、移了哪份材料、何时接受”，不能与自然过程各改一份高程后重复下切或供沙。

运行水态沿第二层维护唯一水/盐/颗粒库存、当前控制域、真实通路和有限交换。挖沟不新增水库，蓄塘形成的R/L空间仍只记相应一份水；施工接触的土层/地下水属于原M/G。工程设施改变几何、接触、阻力或有来源的机械功，不另编“设施供水量”。

运行宿主负责接收操作、工料和施工时间，组织同源物理过程、受影响域、保存与相容发布；核心过程继续在C++，不会因宿主是Godot就另写一套随意引水算法。导出/存档按第四层引用来源、版本和能力；第五层只表达接受状态，不以水面mesh或材质决定通路。

普通土方可用适用的地表表示，开口、地下接触、悬挑或阻水实体需有足以支持实际作用的局部几何。旧高差格可作为操作/表示参考，不能作为所有结构的唯一水力模型。更改显示LOD、工具笔刷或格子编号不自动改变物理地形、库存和流向。

较为真实不要求全世界逐粒泥沙、逐孔隙或全尺度流体精算。以后选择能保留**控制高程、有效储水空间、实际连接、有限交换与响应时长、相关材料能力**的适用抽象；细化应能改变或证实玩家关心的蓄排判断，不能为无关微细过程增加操作负担。粗化不能抹掉一处决定能否排水的土埂/涵洞，也不能把所有土层压成同一漏水率。关键信息缺失应补输入或限制相应工况，不能用永久“未知”代替已支持范围内本应可理解、可操作的环境。

## 4. 工料、作业面与时间怎样相容

### 4.1 挖出的材料有去向，填入的材料有来源

挖掘从实际层序/材料库存移除，进入可记录的工地堆料、运输或其他真实去向；填筑从相应供体扣除后形成实体。土、砂砾、岩块与完整基岩不能仅由一个深度阈值互相替代，普通镐也不默认能移除任何岩层。具体道具“份”与质量、固体密度、孔隙/松散体积及压实的换算以后核定；不能一份料既留背包又增加堤体，或把松方、压实方、岩石实体体积当同一量。

湿土挖移同时处理原孔隙水的去向：可以保留于实际湿料、向真实通路排出或进入相应控制空间，不能材料移走就删水，或原M/G与背包各留一份。工地堆料、拆除物、冲毁物和进入水中的颗粒沿同一物质账转移，不把全部挖方自动当即时悬沙，也不因清缓存让它们消失。

正常手工在可达作业面上分段完成，水深、支护、材料和工具限制实际施工；不能隔着厚岩或深水对看不见的格子无限挖填。涉及水下施工、临时围护或排水，只在方法与技术条件成立时支持，缺能力就明确，不强制玩家涉入未知深水。当前岸距禁区可保留为旧工具限制，未来是否安全不能只以“离岸几米”判断。

实际已占用的玩家/构件空间也不是空白填筑区；不能自动挪走人、推开实体或只改碰撞来强制接受不相容终态。既有可达与脚下填筑限制可在适用处保留，具体占据、支护和局部承载判据以后按实际输入核定，不在本层展开人物伤害或岛级毁坏玩法。

人工搬运维持几十米内的合理范围；长距离或大土方需要实际运输/设施与工地组织，不要求玩家抱料步行一公里。这里不确定施工配方、重量、劳动经济或运输系统代码，只保留来源与可达性约束。

### 4.2 施工是实际过程，不能把长地质步当一锹

每个已完成施工增量有对应工量、材料和世界过程区间，水情在同一物理时长响应。当前交互p_delta/读条秒数是旧操作实现，不直接作为岩土可移动率；以后明确交互节奏、世界时钟、实际工时与物理过程的转换，不能施工只过一帧而水按多年外排，或每帧重放同一工量。

开局不带入生成阶段的地质加速。暂停、调速与后台补算沿第一/四层时间契约；数值迭代不是额外施工、来雨或侵蚀时长。工程或洪水可发生局部事件变化，但不每天强制换槽，也不把工程影响全部冻结到地质历史终点。

## 5. 从操作预览到接受状态：工料、几何与水一起成立

预览只表示可得资料支持的施工范围与可能影响，不扣料、不挖地、不灌水。能预报的只给相应结果或范围，未知明确；在地形、通路或水力资料不足时，不能展示一条保证灌满的蓝沟作为承诺。

推荐接受顺序：

1. 在已接受状态上定位实际岛体/作业面、材料、已有设施与施工方法；核对目标和来源，不用最近河中心线代替脚下水/地。
2. 按实际完成的工量提出材料移除/放置、结构开口或控制变化，保留原水盐沙与局地位置。
3. 在该过程区间更新实体、层界/孔隙、床岸/出口与工程接触；与水的移动边界、地下相对渗流及有限输运耦合，必要时细分，不能先把几何压进原水再删超容水。
4. 求相容的控制域、库容、水位/水头、通量、材料交换和局部受力。水压力/反力或材料能力使候选终态不成立时，限制实际安放/推进或给出未支持工况，不建立无物理空间的“待处理水库”。
5. 校核对应材料转移、供受体水盐沙账、过程时长和依赖，再共同发布当前实体、碰撞、水面、查询、HUD与工程状态；物料取得/消耗与真正完成的增量对应。
6. 保存接受时刻、来源与工程进度。重试、迟到异步结果或恢复不能重复给材料、重复扣料、重播来水或再次计功；部分已完成施工不能因后续失败全部假装未发生。

这不是具体事务类或求解器设计。它确定的是可重复检查的接受边界：不能新碰撞配旧水面，也不能先发材料奖励再假定相应挖掘一定成功。操作失败、未解析与真实没有水分开反馈。

撤销未接受的预览不改变世界。已经施工并发生实际排水、输沙或塌落后，“恢复外形”是新的回填/拆除过程，需要材料与水态响应，不是把水、盐沙和经过时间一起回滚。开发自由笔刷/无限料模式要明确为诊断或另有外部输入的情景，不作为普通玩法守恒与工时验收证据。

施工顺序也会成为现场选择：例如条件许可时先完成干侧沟段、保留最后控制土塞，再有准备地切通；需要围护、导流或排水时，临时工程同样占据真实空间、有工料和水态响应。它们不是自动附赠的安全罩，也不是每次都必须搭建的流程。未完成工程按实际已形成的几何起作用，暂停施工不会冻结水；开口/闸的分次调节同样受实际技术、可达性和有限能力约束，不把预览中的完工状态当当前事实。

## 6. 挖沟与改道：有沟不等于有水，有路不等于立即满流

### 6.1 连通要看完整路径和控制点

开沟只改变几何。引水要有实际水源/可供库存、可达连续通路、相应水位或总水头条件、有限输水能力和实际经过时间；近邻、画线、渠底某一点够低都不充分。地表明渠核对全路径的床脊/鞍口、进出口和上下游水位，不能只比较起终点而穿过中间高埂。

尚有最后一段土塞时，低处干沟可保持干；切通后水先占据真实通路并可能入渗、存留、输沙，再抵达远端，不瞬间按新总库容分配。源供水不足、损失大或通路能力小，渠可以只有一段有水、间歇输水或尚未充满。零通过流但仍存水不判干，按第二层保留液水连接/近静水/孤立潭。

地表自由水不会因玩家选了“流向”就越过更高屏障；封闭管/承压地下路径另核对总水头和实际连通，不一概用渠底坡向替代。通路存在和当时有流分开，回水可使交换减弱或反向，不能全场重算一棵永久单向D8树来代替第二层。

### 6.2 分流、旧槽与上下游影响

新支路从原水系分走的是实际交换，不能原河继续拿完整旧流量、新渠再得到同一份水。分流比例由当前几何、两端水态、阻力和储留决定，既可能改变上游水位，也可能影响原下游；不以给定百分比保证两边都有稳定水。

改道后旧槽里的水仍在原位置，可按剩余低点、地下交换、蒸散和实际通路衰退，不能随源河ID瞬移到新渠，也不把旧河一帧清空。新来水沿当前路径，历史流动统计按新旧对象范围分别解释，不复制前身的“常年”标签。

新渠或切口中的冲刷、淤积、侧蚀、塌岸和床料分选沿第三层实际条件响应；工程不永久锁死初始断面，不能只改宽而不动材料。硬质衬砌或护岸若以后可用，要有真实材料、几何、接触和维护，不自动成为无限强度/不渗漏边界。局部变化可能传播上下游，但不能为了展示变化而强制冲成大河。

## 7. 堵河、筑堤、蓄塘与溢流

### 7.1 阻水效果来自实体和接触，不能只看碰撞

土埂、堤体、坝/闸或其他阻水构造需核对实际占据范围、与床岸/地基的接触、开口、材料透水与可承载能力。只堵主槽中心，水可以从低岸、洪泛地、孔隙或其他真实开口绕行；水未绕行也不证明完全不透水。普通门、墙、道具碰撞或透明度不直接定义水力密封。

普通建筑或堆料若确实占据水路，按所支持尺度纳入空间/阻力影响；模型不支持相应阻水/承压工况时明确，不让同一实体一边挡人物、一边被假设为无限密封坝或完全不存在。有限渗漏、绕流和出水由实际路径给出，不能统一减一个百分比称为防渗计算。

填入有水空间会排挤原水，需在真实空间与通路中迁移；受水反力限制的放置/形变回到相容更新。不能完成一个塞不下原水的几何终态，再按新容量删水或在账外保存超容水。

### 7.2 蓄水与排水都是有限过程

新挖坑/塘没有新水来源。初始水来自原地表/孔隙状态的实际转移、降雨、径流或地下交换，不能默认满塘，也不能默认干塘而删除原有水。湖塘沿同一R/L及盆地几何组织，地下土水仍属其原物理空间，不因同一平面位置重复储水。

堵住出口可以使实际来水逐步蓄积，上游水位、岸地淹没和其他出口/地下交换共同变化；低供水时未必涨到堤顶。原下游可继续释放已有水，不能堵口瞬间全干。开启或切低出口后，按当前控制口、上下游水位和有限能力排出，不能一帧清空整塘。

水到达真实低口后可能溢流，也可能先被下游顶托；局部越顶、自由跌水和淹没出流按适用状态处理，不保证所有口都像同一种人工堰。堤顶以外仍需真实承接域，不能用海面低水位吸走全岛水。水真正离开岛缘才记相应外排；下方若有明确接收域才另转账，不在空中造河床/冲积平原。

### 7.3 工程会维护、改变或失效

冲淤会改变进水口、渠道和塘的能力；清淤将实际沉积转入工地物料，不能清空一个统计值却不搬材料。局部掏蚀、渗流、孔压与岸体/堤体稳定沿实际材料及第三层适用过程响应，不能土方一落地就获得无限强度或把退水标签直接当崩塌开关。

冲毁/塌落物仍在世界中，可能堵新口、入床或被有限输运；不直接消失、不免费恢复。设施开口/拆除有实际变化时长和材料去向。这里不展开整岛或骨架摧毁模型，不用玩家工程触发无依据的核心泄压或无限泉流。

## 8. 地下水、井、管道与泵的最小接入边界

| 情形 | 本层所需的物理连续性 |
| --- | --- |
| 挖坑接近/切到含水带 | 根据真实层序、接触与饱和/包气状态交换；低于某个摘要水位不代表必有无限涌水，干裂隙也不瞬间当满水管 |
| 新坑增加空间 | 由实际补给有限充水；邻近地下储量和水头可下降，不按新孔隙容积自动满水 |
| 压密/回填/封堵 | 改变孔隙和接触，原水保留并有限排泄；固态约束压力不是地下水水头，封路不同时排干两侧 |
| 井/排水接入 | 是与实际含水域相连的开口/控制空间，抽排扣该供体，可能影响相邻泉、河床交换或水头；井名不产生固定日供水量 |
| 管道/涵洞 | 有真实入口、出口、管内/通道储量、开度和输送能力，两端引用接受水态；接触不等于已充满或瞬间同水位 |
| 泵或其他提升 | 只有实际设备/技术、可用机械功和对应能力时才支持，扣实际水源并给真实受体；不能将低水无代价搬到高处 |

明渠、涵洞、封闭管与地下渗流是不同适用域，不能共用“起点较高所以每秒转一份水”的脚本。超出已设计能力的承压、充水/气阻或连续水柱过程明确未支持，不按管线标签自动形成跨山虹吸或无限流。具体设备、压力工况、动力参数、管网算法与井结构以后细化，不据本稿宣布当前科技已拥有任何泵具。

输送盐和颗粒按现有物质库存与适用过程，不能水到出口自动变淡、沙无条件穿过所有管口或拦网。饮用、灌溉/生产实际消耗和完整道具容器留第七层，本层只保留供体、真实路径、受体与一次转账的约束。

## 9. 局部计算与远域：物理影响不能按显示块截断

选择受影响域先看改动的实体/开口、控制高程、相连地表水域、盆地层级及地下接触，再沿实际上/下游和水头响应扩展。一个小缺口可能影响远处盆地，一个大填方也可能与河水无接触；不能固定“笔刷外几格”或一个图形tile就是完整水文范围，也不要求所有操作都全行星重算。

近域可以细化水力/床岸，远域保留相容粗化过程；边界位置、朝向、双方水位/水头与同区间累计交换共享，供体扣受体加只一次。若回水、改道、洪泛或地下响应到达边界，更新/扩大耦合范围或明确未解析，不能继续钉旧水位/旧Q曲线让影响在边缘消失。

多尺度或不同子步仍使用共同接受区间和真实驱动。相邻域未准备好时按第四层共同等待或采用经过校核的相容简化，不让一边继续扣水而另一边失联，也不创造“等待水库”。数值误差、真实干湿与尚未加载分开；场景离屏不是物理墙。

卸载近景只卸载表示。已经完成的沟、堤和开口，以及局地库存和工程能力保留；不能飞走后自动复原自然河或停止远端影响。远域后台推进/延迟补算沿保存状态、实际天气与边界历程，输入只结算一次；资料不足时标缺项，不用离开时长乘平均Q补出结果。相机回来看时先取得相容几何、水态、查询与碰撞，再交第五层显示，旧泡沫/反射历史不跨新屏障复用。

## 10. 当前几何、版本与存档怎样保存

自然源身份/历史、当前实体/层序/材料、玩家完成的工程及变化、运行水盐沙/通路、接受时刻和驱动共同解释世界。源几何保留作来源，不意味着自然侵蚀后仍永久叠加旧高差：例如堤体实际被冲走，不能下一帧又用“原面+永久编辑级数”让同一堤料再长回来。

工程定位绑定真实岛体/实体、当前物理坐标与源版本，换锚/改显示LOD不迁移工程。自然慢变、洪水冲淤与玩家操作共同更新接受状态，分别记成因和物料，只在有可靠对应时复用原工程表示。当前旧编辑格原点相等也不能证明两版实体相同。

按第四层区分自然源包、运行存档和可重建派生缓存。保存足够的局地材料/水态与工程状态，不能只保存一个高差文件和日期，再重新预热水文。玩家背包/堆料与实际已完成施工需对应同一接受进度，文件各自用了临时改名不代表跨文件已经一致；中断恢复不能多发一遍材料或丢掉已经排走的水。

旧工程格错位、源包/语义不相容、缺水态或解析失败时保留原文件和明确冲突/恢复方案；不静默清空营造，也不把旧渠按新世界容量重新灌满。若未来需要迁移，先在副本审阅来源映射、局地库存与缺项，按明确授权执行；本轮不读写用户存档、不更换剧情目录、不实际转换旧数据。

## 11. 操作反馈怎样说明因果

### 11.1 用现场线索与可得信息解释

复用既有工具选择、准星、可达提示和分段施工方向，未来提示优先解释玩家能作出的判断：哪里是实际作业面、能挖哪种材料、为何被障碍/水况或工具限制、施工完成多少、是否已经切通、来水是否不足、出口是否被下游顶托。正常流程不要求用户阅读模型版本、控制体编号或求解日志。

预览与真实水态用明确状态区分；预览箭头若只是地形可达推测就这样标，不假装预测了流量或几分钟必满。水没有马上出现时可区分未切通、真实供水/水头不足、通路储留/入渗延迟、能力未解析与计算/加载未就绪，不统一回答“没水”。零Q但存水、干渠和仅土层湿润按第二/五层表达。

按第五层保留可见水线、真实高低关系、湿态、实际沉积和渗出等线索，并将真实观测/历史与估计分开。单张晴天画面不能证明旱期供水或洪水能力，浑水也不保证露出河底；没有测过的地下层界、未来天气和结构强度不变成全知提示。若以后提供测量、标记或记录，精度、可达性与来源需相容；本轮只定信息职责，不新增仪器和HUD实现。

### 11.2 观察—小步施工—复查—调整与维护

建议正常过程是：辨认来水和去处、选定一个具体环境目标 → 用已有线索判断限制、选择可承担的工程规模 → 先做能辨认效果的分段施工，按条件保留控制与余地 → 看新水路的实际到达、上/下游水位和岸地湿态 → 再决定继续、调整开口、维护、缩小目标或停止。小试本身也可能改变水沙，不能免费回滚；没有安全的小试条件时可先观察或换址，不强迫试错破坏。

反馈分三种实际历程：施工和接水后的局部变化；来水涨落与一次事件中的蓄排；较长时期的渗漏、淤积与材料变化。前者应在其物理响应发生时可辨认，后两者沿同一世界时钟逐渐显现，不承诺几秒完成所有过程，也不要求为获得第一条有效反馈先空等多年或一次罕见灾害。可从合理规模的目标、阶段结果和真实记录获得进展；以后若有统一时间推进，仍遵守第一/四层，不单独加速淤积、洪水或岩土来催促玩家。

比较效果需记录对应来水、下游状态、施工阶段和已过时间；雨停后的自然退水不能全算工程功劳，来雨变大后的涨水也不自动判工程失败。正常游玩依据实际历程获得有限认识，未来验证可在独立副本用同源驱动比较有/无工程，副本结果不写回游玩库存，也不把预测当已发生历史。改造成功应能解释“何处、在什么条件下改善了什么、代价落在哪里”，不靠隐藏随机成功率决定水是否服从已有通路。

开发诊断以后可查看同版断面/控制点、局地库存、边界累计交换、材料去向、接受时刻与来源版本，支持暂停和分步因果核对；它不替代普通玩家反馈，也不把开发自由料/固定有利水情当验收。这里仅讨论未来信息职责，不新增开发工具，不修改`src/dev_manual.cpp`。

## 13. 以后怎样验收及与前五层的关系

以后获授权再按对应改动做定向检查，使用同版真实源、接受水态和实际时序，不固定有利来水或开发无限料展示：

| 情景 | 应核对的结果 |
| --- | --- |
| 干地开低沟但仍隔土埂 | 沟可以保持干；不因两端相邻、渠底低或工具画线而连水 |
| 切开最后真实控制点 | 湿润/储留/输运有限推进，源供体有相应扣账；不瞬间灌满新容量 |
| 低供水或高损失渠道 | 可部分有水/间歇；不保证全长和原下游同时满流 |
| 分流与改道 | 真实分配与到达时间，原下游及旧槽存水继续响应；不复制流量或瞬移原水 |
| 坑/塘新容积、原有湿土 | 新空间不供水；原孔隙水/地表水有实际去向，不默认满或删原水 |
| 土方与结构阻水 | 完整接触、绕流、有限渗漏和低口控制；碰撞/门名不决定密封 |
| 堵口/抬口、开闸/切低口 | 蓄排有限、下游可顶托；上游不瞬间满、下游不瞬间全干 |
| 有水空间内安放实体 | 原水在真实空间迁移，反力限制不相容终态；无虚拟超容水库 |
| 触及/封闭地下通路 | 原库存、饱和/包气与能力决定响应；不从岩石承压造泉，不封路即删两侧水 |
| 清淤、冲毁和自然床变 | 材料真的转移，工程能力随当前实体变化；不会下一帧按旧高差长回已冲走的堤 |
| 普通工料与开发模式 | 质量/体积/孔隙和完成工量对应；自由笔刷单列，不作为普通守恒证明 |
| 物理域越过局部块、离屏再来 | 边界交换一次、影响不被显示边界截断；重载不重置工程或水态 |
| 中断、重试和存档不相容 | 不重复奖励/施工/输入，保持上一完整接受状态及恢复证据；不静默清空 |
| 自然环境与施工前判断 | 来水、低口、低地、湿土和床岸差异有实际来源；能在支持范围内解释哪里宜蓄、宜排、受顶托或不宜改造，不用任务点代替环境 |
| 阶段施工与正常反馈 | 完成一段沟、最后切口、有限调口等按实际条件产生可辨认结果；观察能区分未通、未到、缺水、回水及未知，不强制先等罕见洪水 |
| 改善、代价与对照条件 | 核对目标位置的水位/湿态/蓄排历程，同时查上下游、地下、岸地和材料去向；记来水/下游历程，不把天气差异算作工程效果 |
| 多种条件与长期保留 | 同一工程在适用的低水、涨水、退水和有沙情形下可解释，正常离屏/保存后效果继续；不要求全情形都成功，也不靠每天强制坏堤制造维护 |

通过不仅看全岛总账，还看真实路径、控制高程、局地材料/水占据、过程时长、物理流向与功、地下相对渗流和模型适用域。总量守恒但瞬间跨山、假满管、按总容量分湖或刚性拖走地下水，都不通过。输入误差不足以判断某次切通时，保留未知或细化，不靠任意阈值硬判成功。

还要作正向环境验收：在自然条件确实允许的样例中，合理规模和技术下的改造能改善所选环境目标；普通信息足以逐步认识原因，改善与不利影响都能追溯，工程结果能在实际后续历程中保留或有依据地变化。有不同可行方向的地点，应看得到选择和取舍；条件不允许时，缩小、改址、保留低地或不修也说得通。不能只通过“水未增减、接口未报错”就宣布已给水利玩法打好基础。

这类验收先针对自然环境与工程反馈；游戏是否有趣还需以后在真实交互节奏、工量与信息条件下试玩判断，本轮没有完成这一证明。饮用、作物、经济、生态和水上交互继续留第七层或用户指定的后续专题，不以本层环境目标预先锁定它们。

前五层保持：第一层有限成因/库存和独立时钟；第二层有限交换与状态分类；第三层真实材料—床岸反馈；第四层同域同版相容发布和三类保存内容；第五层只显示接受事实。玩家改造必须通过这些约束，不能为玩法另造水、土、盐、沙或永久深槽。47米原始自然河现场仍未验证，第六层的人工引水案例不能替它宣布解决。

本轮完成的是只读调查与设计材料，未执行上表的物理/游戏检查。所有未知数据、物性和代码模型明确留后续，不以动画展示“引水成功”冒充当前游戏已经具备该能力。
