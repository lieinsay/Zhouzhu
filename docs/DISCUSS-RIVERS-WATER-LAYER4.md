## 1. 本层选择：一份物理事实，多种受约束的表示

推荐主链：**生成器形成同源岛体、层界和连续床岸 → 导出包交付带来源、尺度与依赖的完整快照 → 游戏在统一坐标中派生显示、碰撞和查询 → 运行水态消费同版几何与唯一库存 → 所有消费者发布同一接受时刻 → 用可追溯的断面与位置核对。**

“同源”不是所有用途共用一张完全相同的网格。宏观地形、局部实体、求解网格、近景三角面和远景LOD可以不同，但要映射到同一物理几何，并守住河岸位置、最深床线、控制口、通路与实体/空洞关系。简化不能把原本相通的河截断，或把两座独立岛接在一起。库存与状态另有唯一归属，不能因为多画一层水面就多出一份水。

本层讨论信息怎样传递和保持相容，不重选前三层的成因。浮石仍是独立元素，金银保留；骨架内高压固态岩层沿受限缝隙有限迁移、卸压膨胀，不变成默认岩浆喷发或无限补给。水、盐、泥沙沿各自真实来源与去向记账，不恢复集水核。生态、生物演化、材质镜头、玩家改地和用水玩法不提前展开。

## 3. 四方责任与交付内容

### 3.1 生成器：形成原因与权威自然几何

生成器负责同一历史下的岛体顶面、侧壁、底面、骨架和层界；连续床岸、真实弯道/洲体/分流、参考控制点、盆底与全部出口；材料库存、地下接触、孔隙/通道及相应水力能力。局部几何必须已经嵌入地形和材料账，不另外导出一份等待游戏再挖的侵蚀量。

同时交付初始水盐沙库存、形成/预热历史、气候与过程时间契约、来源/前身后继记录、模型适用域、误差和未解析区。不能仅输出地貌标签、河宽和“计划有洞”就让游戏自行完成成因。第一层有限岩层更新须能追到实体位移、层界、剩余质量、孔隙和通路变化；封存固体应力与地下孔压是不同字段。

### 3.2 导出包：保持事实、声明能力并阻止混版

包是可校验的快照，不是新的地貌求解器。它做明确的坐标/单位转换、分块、精度编码及受约束的派生LOD，保存依赖、内容校验与缺项。几何、水力几何关系、初态、天气、LOD、点位必须能追到相容源版本。输出前已有错误或缺项就明确报告，不在导出器补河宽、出口、地下网或水量。

每类信息还声明：它是权威物理量、受约束派生量还是描述标签；空间支撑域与有效时间；精度/缺失/不适用及来源。语义岛ID、材料类别、实体身份和通路端点不能像高程一样作数值插值；0、缺失、未加载和不适用分别表达。内容校验只能证明字节对应，数值范围、实体接合、端点引用、几何依赖与物理空间另作语义校核。某个文件完整也不证明整包相容。

推荐内容分为：世界/坐标时间清单；同源实体几何及局部细化；源水系与地下接触；初始库存/当前接受水态；统计与历史；显示LOD及派生索引。这里只确定职责和必需信息，文件名、二进制布局、下一版本号、类结构、字段编码和具体误差数值留以后细化，不预定“v9”或某个新代码模型。

### 3.3 游戏：精确解释与受约束派生

游戏负责读包、局部坐标/换锚、渲染网格、碰撞、查询、流式加载与HUD表达；所有派生结果都有源引用和版本。它可以改变三角化、可见性和内存布局，不能改变物理床岸、补造岛底、重新排河、用贴水面删碰撞或为防露底抬水。

资源读取沿用Godot `FileAccess / DirAccess`，覆盖编辑器与PCK内`res://`路径。导出到游戏的事实不依赖玩家机器上生成器`out/`目录存在。开发视图可展示源面/派生面差异，普通用户界面只显示理解环境所需指标；校验哈希和模型内部细节不塞进产品流程。

### 3.4 运行水态：同一几何上的唯一库存与有限过程

运行水态负责第二层的R/L/M/G等库存、物质归属、真实连通/通量和水位，消费第三层的实际断面及第一层地下物性。当天湿边、局部水深、水面域与流向来自这个接受状态，CPU、shader和HUD读取同一份结果。mesh仍可作为水面表示，mesh不承担供水或储量定义。

自然床岸更新如果以后进入游戏运行，使用生成器C++核心所定义的同源过程和材料账；宿主调度并不意味着游戏可另造一套算法。谁在进程内运行、哪些域离线、采用何种求解器留后续模型阶段。第六层的玩家操作接口、改地权限与引水玩法本轮不设计。

## 4. 连续几何怎样传递：宏观面与局部实体共同组成一个世界

### 4.1 在适用范围保留高度场，在必要位置交付实际多面实体

普通单值地表可继续用宏观高度场与源插值规则；河床、岸脚、陡崖、出口、深槽和层界交接处提供源过程支持的局部细化。源分辨率与重建误差明确记录，增加显示三角形不等于新增地貌信息。100米采样不足以定义的窄槽，必须由上游细化与过程给出，不能从粗格数值平滑后宣称已经解析。

悬挑岸、天窗、洞穴、岛底及局部地下通路采用实际多面/实体边界；每个平面位置可以有多个表面，查询要知道哪一实体、哪一侧及所在空间。宏观高度图只是该处可适用的摘要，不允许用“最高面”堵洞或用“最低面”串通不相邻的水域。连续层界保存空间位置和材料身份，出露岩性栅格仍可作摘要，不能取代整个三维层序。

系列断面是同一连续床岸的可定位切片，不能每个断面独立补一条对称槽。断面需有世界位置、截面方向、沿程定位、左右顺序及真实床岸折点，允许偏侧深槽、多个湿区、干洲、真实逆坡和硬阶坎。普通缓变单汊可用具有明确重建规则的断面间表面；强弯、汇流、分汊、出口及拓扑变更区交局部面片，避免最近中心线切换或交叉断面造跳面。

### 4.2 局部细化是替换对应表示，不是叠加第二轮挖槽

每个局部域声明覆盖边界、母几何来源、被替换的贡献、接合条件及材料/水力范围。母格的河谷可能已切过，局部域输出最终实体边界，游戏不能再减一次`depth`。细化外接到同源母面，普通面连续处接合，源上真实的崖/断层则保留折断关系；不以通用平均或最低包络把两条不同高度的河、隔水层或两座岛合在一起。

母格与细域材料只归账一次，水力容量和地下接触重新从最终组合几何得到。导出若把域切成多个块，相邻块共享同一边界事实/定位，并记录端点接合；合流处水只属于一个对应控制空间，不能为每条中心线各叠一份水面和库存。

### 4.3 岛缘与地下通路也是源几何

岛缘轮廓、真实出口唇、顶面/侧壁/底面连接及每座岛身份一起交付。水面到达真实自由出口后转为出流域；陆地水面裁切在实际边界，离体落水另作显示域，不在空中延长河床或制造冲积平原。瀑布的物理出口与装饰帘长度分开，显示帘不参与上游库容或河槽定义。

地下输出区分潜在几何接触、有效导水/储水性质和当前湿润/饱和/通量。画面不显示的通路仍能改变水态；关闭显示不等于关闭地下流。骨架结构缝隙可迁移固态岩石，是否导水要有另行来源证据，不用一个“裂隙”布尔值同时代表两种过程。

### 4.4 断面、库容和插值表也须能回到连续几何（设计已确认，数据与实现待验证）

只传“正确宽深”仍可能出现容量不一致。源断面切片、A/T/湿周关系、盆地水位—淹没面积—库容以及求解单元的空间占据，要能回到同一组合几何与同一测量方向。普通段可采用可核对的断面间重建与积分近似；复杂节点使用实际局部面。求解网格与显示网格不必相同，但它们对应的物理控制空间和误差要明确，不能求解仍用矩形容量、显示改用曲线后只比较最宽与最深两点。

预计算曲线/表格是派生缓存，记录源版本、适用水位/连接分支、重建/积分方式及误差。固定几何与连接分支下，水位增加时实际蓄水空间不能凭数值插值变小；越过真实鞍口或床脊要启用对应连接/分域，不能拿一条平滑表把干屏障消掉。超出有效范围、地下空间转承压或表面拓扑改变时，重新取得适用关系或标未解析，不无依据地外推。

精度不仅影响小数读数，还可能改变通路。编码舍入、插值过冲或近远重建若把两个关键高程合到一起，可能删掉薄水层、抹平岩槛或造出假连接。导出应核对关键控制点、局地占据和通路关系；误差若不足以判定真实干湿/连接，就保留不确定性或要求上游/编码细化，不能在游戏抬水、补岸或用任意阈值纠正。容差和精度分配以后依据特征尺度与误差核定，本轮不指定统一毫米数。

## 5. 坐标、高程、单位、时间和玩家尺度

推荐保留现有群局部米制方向：**x东、y上、z南**；行星CPU坐标和群/岛变换保持双精度，渲染块采用局部原点。清单明确原点、轴向、手性、矩阵/变换约定、投影、基准球半径、岛姿态、格心/格角和高程基准。源栅格的row/col及km坐标只通过一个有说明的转换进入游戏，不各处独立反号。

当前`gen_export.cpp`源点采用`x=ox_km×1000+(col+0.5)×res`、`z=−oy_km×1000+(row+0.5)×res`；DATA-GUIDE明确高程相对浮层基准（约1atm的零点），并非海面、云顶或当地地面。现有`planet_frame.h`部分旧注释仍称云顶以上，而`VerticalDatum`与当前基准已经区分；新清单必须消除这种歧义。高程/水位/层界/岛底沿用同一基准，整体岛变换只加一次。整岛平移不增加相对槽深；倾斜及层内相对变形须重新核对世界竖直方向和水力关系，静水面不能随着岛旋转成斜面。

保留CPU双精度、局部块单精度、现有AEQD与换锚方向。源的群坐标到实际行星位置的投影/物理度量，与相机附近的显示弯曲、远景距离压缩分别声明；不能笼统把所有球面关系都当美术变换。长度、面积、体积和控制高差使用同一已声明的物理度量；群平面坐标使用米，不保证任意两点平面距离与球面距离都精确相等。采用局部平面近似时交代范围和误差，不能各消费者独立选半径或面积口径。显示压缩不回写床坡、水量和物理长度。

重力/竖直及高程方向也引用同一源基准。局部静水近似的“水平”指相应重力势基准，而非任意岛体坐标的y常量；行星曲面上的表示按该基准映射，不能随岛姿态旋转。地形、水面、人物和标注采用相容显示变换，查询从场景局部坐标返回权威坐标；切换群锚不能改变同一物理位置的高度或水深。河断面的横向方向与沿程流向明确，左右不由相机视角决定。这是传递既定几何的度量契约，不在本层新增重力或浮力公式。

| 量 | 推荐契约 |
| --- | --- |
| 长度、高程、槽宽/深、层厚 | 米；绝对高程和差值分别命名 |
| 面积/容量 | 平方米/立方米；汇水km²只在显式命名字段使用，不混入计算 |
| 流量与物质 | m³/s、kg及kg/s等明确口径；水主账与液水实际占据体积沿第一层区分，盐/沙另记质量 |
| 时间 | 物理秒、世界历日/历年、现实钟速和地质历史分别声明；正常默认2400现实秒/游戏日不是物理日长 |
| 玩家尺度 | 1场景米对应1物理米；当前胶囊/模型名义高1.8米、半径0.35米，现场仍核对父节点和全局变换 |
| 精度/缺项 | 每类几何和水态给分辨尺度、误差、适用域与缺失状态；缺失不编码成0米、干槽或默认满水 |

地质参照年与一亿年背景沿第一层6.2；生成阶段的地质加速不进入游玩。日期显示偏移、暂停、调速、实际过程推进和状态时间分别记录，不能只改日历文字便结算多年释放或供水。均值统计附实际窗口、气候/几何版本与有效样本。

本层不改人物大小、镜头或视觉夸张。以后对47米问题保留用户实际位置/日期和全局玩家尺寸，同版测量；名义模型尺寸核对不能替代现场验收。

## 6. 宽与深必须带位置、参考和时间

所有断面指标绑定同一几何版本、截面位置/方向及参考面或当天水态。`width`、`depth`不能单独承担多个物理含义。推荐如下：

| 指标 | 定义与必要附属信息 |
| --- | --- |
| 河谷宽/历史河槽带 | 有来源的地貌活动空间与历史范围；不是当时有水范围 |
| 参考河槽跨度 | 有依据的两岸控制点和参考面之间的实际跨度；注明bankfull/漫溢/其他参考，无法辨识时缺失 |
| 活动主槽宽 | 当前形态阶段中实际主导输水/输沙的主槽床岸范围，含形成历史和判据窗口；不得把当天湿边或谷宽直接当它 |
| 多汊活动范围 | 各汊及洲体分别定位；无法唯一识别主槽时输出各汊和整体活动带，不强挑一条最大槽假装全河 |
| 当天湿宽之和T | 当前断面内各实际液水湿区横向宽度相加；干洲、干滩不计 |
| 最外湿边跨度 | 最外两湿边间距离，可包含干洲；另列，不伪称连续水面宽 |
| 岸顶至床面下切 | 指定左/右岸或阶地参考点与指定床面点之间的高差；露岸包含在内，不能等同水深 |
| 参考最大槽深 | 指定参考面到参考湿域实际最深床面的高差；与参考槽跨度属于同一参考，不默认最低床点在中心 |
| 当天断面平均水深 | 普通竖直断面下过水面积A除实际湿宽之和T；T=0时不计算，以状态表示干/未知 |
| 当天最大水深 | 同断面当前实际湿区中最大的水面至床面垂向差；不是整条河最大值 |
| 当处局部水深 | 当处实际液水水面与同一湿域中接水床面之差，绑定空间位置；河心与岸边不同，空洞或上下叠水域要选对域 |
| 均流/时间平均几何 | 均流对应的一次水态、实际水深时间平均和面积/湿宽时间平均分别输出；不能以平均Q代替全部均值 |

活动主槽是形态/过程对象，可能随冲淤、侧移或新分汊改变；当天水位变化通常只改变湿区，但真实事件改变床岸时更新活动范围及版本。具体识别阈值和代码算法留后续核定，缺乏形成历史时明确不支持该指标，不能由v1的固定宽度直接升级成活动主槽宽。

普通段的A、T、湿周和水力关系来自实际源断面；多湿区分别记录水面域与连接，不能把两个不同水位的独立水潭合算为一条均匀河。强三维喷流、悬挑/承压满管等不适用开渠A/T水深口径的区域注明模型域，不能靠一个公式概括。洪水进入实际洪泛空间后，洪泛面积另有空间归属，不塞入参考河槽宽度。

水态还区分时刻值与时间区间累计量。一个时刻的Q不直接当作整段时间已搬运的体积，某日平均Q也不是洪峰瞬时Q；边界实际累计交换要有起止物理时间。流量正负依所声明的断面/界面朝向，不因河段名为“上游到下游”就禁止回水反向。断面平均流速、局部速度向量和未解析状态分开，不能由Q/A声称每处流速相同。m³/s采用实际液相输水体积口径，水主账的参考密度水当量与之转换时声明密度、组成及近似；盐质量与颗粒通量仍分别记账，不强制随水同比。这里只补信息口径，不设计水流推力或航行玩法。

## 7. 源面、可见面、碰撞、水面、查询与HUD怎样一致

### 7.1 固体表面共用权威组合几何

近景可见实体和可行走/接触碰撞由同一组合几何派生；水力所用床岸也引用该面。相同点、相同域的差异给出有来源的误差说明，误差要求按床岸、控制口和玩家接触等用途制定，不能统一随意取一个百分比。碰撞简化不得填平深槽、移走岸脚、堵洞或把已露出的滩变水底。

查询使用权威几何与对应空间域，提供表面/体查询，而非一概“按x,z返回一个高度”。站立点查实际可接触上表面；水深查液水底边界；地下与岛底有不同查询上下文。最近河中心线可用于选取待检查河段，不能证明玩家脚下有水。绘制用的接缝裙边、遮罩和装饰石不参与源库容，也不作为新的河床碰撞去掩盖主面差异。

### 7.2 水面从同一接受水态派生

水态交付当前自由表面/压力域、实际湿区边界、覆盖/液水状态和源几何引用。shader可插值已支持的状态、表达波动或覆盖，但不能独立从Q再估一套水深与湿宽。几何中的水面位置和显示偏移区分；避免深度冲突的小显示偏移不能进入查询、HUD或库存。

相邻河湖/合流接点使用同版连接和状态：近静水域共同水位仅在第二层适用条件成立时采用，窄口有交换不必同水位；干洲与孤立水潭保留。水面不按“最近一条河的影响半径”铺满，湖面、洪水和河面之间无重复面积/库存。

地形真的高过水面时应露出；若源与派生不符造成拱穿，查几何/状态/精度，不能统一抬水、删地面或减碰撞解决。水面的包围盒和可见性覆盖实际状态范围，shader改变水位后不能仍以旧床面包围盒错误剔除；剔除仅影响显示，不能删除水态。

### 7.3 查询与HUD来自同一入口

统一查询返回物理位置、是否液水/有覆盖/未知、水面域、局部床高与水位、当处局部深，以及可选的同断面指标。断面平均、最大深、参考槽宽和当天湿宽明确命名；查询失败与真实干涸分开。HUD普通信息优先当处状态，需要断面摘要时标“断面”，参考宽标明口径，不再把河心/最大深称玩家脚下水深。

冰雪覆盖、开水面可见性与液水存在分别表达。冰盖下有液水不按“看不到水面”判干；冰面/积雪顶不作为液水水位或河床。具有顶盖/承压的水域采用对应空间和状态口径，不能强套自由水面深度。未加载、包不支持、数值误差内未解析与真实0水量也不能都返回“干槽”。这些区分延续第二层，不展开冰雪材质或生态。

HUD、开发探针、碰撞、CPU查询与显示在一个可追溯接受时刻对照。动画中的人形只帮助解释局部/断面差异，不是实际玩家尺度验证。当前`get_river_at`与`WorldGround::water_depth`的双入口列为替换事项；本轮不修改它们，不未经调用链核对宣布已找到现场bug。

## 8. 几何慢变、改道、合并/分裂与地下变化：同步的是接受状态

### 8.1 版本分工

至少区分：格式/语义版本、生成模型/配置来源、世界身份与历史分支、物理几何版本、层序/材料与地下接触版本、拓扑版本、接受水态序号及物理时间、派生表示版本。具体拆分方式留后续；关键是依赖可验证，不能只用一个commit或seed代表整套世界。

水态显式引用其计算所用几何、通路、气候驱动和上一个接受状态；派生网格/碰撞/查询引用同一物理快照，LOD另有简化版本。来源对象ID与当前控制体ID分开，ID复用不能隐含库存继承。几何改动未影响的域可继续复用，但必须证明其边界与依赖相容。

### 8.2 从t0到t1的相容发布流程

1. 在已接受的t0状态上提出带实际时长和材料来源的形变/床岸更新；保留原水盐沙的位置与库存，候选结果不直接发布。
2. 在该区间处理移动边界、地下相对渗流与水沙输运；控制点切通、封堵、分断或快速形变时细化/耦合，水反力制约塞不下原水的候选几何。每个实际输入只计一次。
3. 生成相容t1的几何、材料、地下接触、拓扑、库容和水态，并保留前身—后继及各自物理去向；物理更新与只换计算网格分别记。
4. 校核局部空间、全账、通路、过程时间和依赖；准备所需可见面、接触碰撞和查询快照，远处允许使用符合保护条件的新派生表示。
5. 受影响连接域的消费者共同切换到这个接受状态。晚到的异步结果如果依赖旧版本或旧请求就丢弃，不能新地面配旧水面、旧碰撞配新查询。跨块/跨河湖连接的事务边界随实际依赖扩展，不仅按一个图形tile划分。

“共同发布”是保持表示一致的规则，不表示所有物理过程在t1瞬间发生。移动边界在区间内已经有实际作用，剧烈事件不能只交换起终快照再插值假装连续；显示插值仅限同域、同拓扑和无关键屏障变化的相容区间。所需消费者未准备好时仍使用上一完整接受状态并明确其时刻，暂停该受影响域的依赖推进或采用经验证的相容简化，不假称它已经跟上当前时间；不能让新来水继续无条件打入冻结旧容量。

暂停/等待不能只冻结一个显示块而让相连上游继续扣水、下游继续收水。相关控制域与边界交换需共享接受区间，或有经校核的跨域耦合与边界累计记录；没有这种能力时扩大到所需连接域共同等待。不能在实体外新增一个“待处理水库”保存无物理空间的来水。显示跟不上而物理已推进时，要取得该物理时刻的相容显示/接触表示或明确受影响交互尚未就绪，不能把旧面标作当前真值。具体调度、求解器与负载策略留模型阶段。

### 8.3 各类变化怎样保留事实

| 变化 | 几何/版本与状态处理 |
| --- | --- |
| 整岛平移/姿态变化 | 更新同一岛体变换与边界；不当作床蚀/沉积，水仍按世界重力和移动边界响应，不旋转静水面或刚性拖走全部地下水 |
| 有限高压岩层挤出/卸压 | 深浅实体、层界、密度/孔隙及实际接触同源更新；固态压力不转成地下水水头，新岩石不直接满水或变河沙 |
| 冲淤与岸体失稳 | 真实局部实体/材料改变，更新源断面、库容和接触；不仅改宽深摘要而锁死可见河床 |
| 改道 | 新来水沿新可达路径，旧槽存水按剩余通路衰退；前身映射追溯来源，不转移全部旧水给新河，不沿两条路径重复给水 |
| 两盆地交换/合并 | 先有可达路径、有限能力和实际交换；足以近静水调平时才共同域；合并时只有一份库存 |
| 盆地分裂/消失 | 保留切断当时两侧局地库存，非静水不强行调平；消失前水需真实空间和有限去向，不删除对象时删水盐 |
| 地下接触开/闭 | 更新真实开度、充填/阻力及路径空间；开启不瞬间满流，封闭保留两侧储量，新孔隙不自动满水 |
| 仅换网格/分块 | 按既有局地占据水体/含水与物质分布重映射，不改变物理路径，不按新容量比例搬水 |

跨版本统计保留对象范围、有效/未知样本及所覆盖的几何/气候区间。旧河的常年占比不复制给所有后继；新河不能因继承名字拥有虚构历史。一亿年级背景、局部事件与日常水文分别计时，实际事件不能等到地质步结束才接入。

## 9. LOD、接缝、岛缘裁切与遮挡

推荐**先保护物理关键特征，再简化表示**。源几何不随距离变，求解和查询不读取当前显示LOD。远处可以不画看不清的水面，但水态、通路和库存仍存在；不会因相机靠近重新供水或换河型。

| 项目 | 保护规则 |
| --- | --- |
| 近景LOD | 河岸、岸脚、最深线、干洲、岩槛/出口和真实折断约束不能被通用网格平滑抹掉；按用途误差与尺度选择网格 |
| 远景LOD | 简化同版实体，保护岛身份/足迹、河槽与出口的定位及水域连通；无法表达窄槽时省略该显示特征并标能力，不把填平后表面当近景事实 |
| 跨LOD接缝 | 共享权威边界或受约束过渡；可用岛体内部的显示覆盖，但不向河槽内补盖板，不跨独立岛、不改变源水力或碰撞 |
| 河谷与母面衔接 | 使用第4.2节源替换范围，过渡不得二次挖槽、填潭或削掉岸脚。硬边界保留其物理接触关系 |
| 岛缘裁切 | 顶、侧、底及水面读同版真实边界；斜向河口按边界求交，不按离岸距离简单缩成较窄河；源出口缺口不补造 |
| 多汊/湖口 | 共享实际局部面与水域归属，不能因中心线带重叠叠水或遮掉干洲，连接口不能被粗面桥接封住 |
| 遮挡/剔除 | 只决定当前是否绘制，不能更改床面、干湿、碰撞或水量；用包含水位/变形范围的正确界限，不能把几何加载遗漏叫地形遮挡 |
| 换锚与细粗切换 | 共同来源/姿态/接受时刻及内容依赖核对后切换；旧异步结果不会覆盖新状态，双绘或空洞是还原缺陷 |

源数据误差与游戏近似误差分别记录；重点检查控制高差和最窄通路，不以全岛均方误差小掩盖一个出口被抹平。毫米至厘米级细节是否物理可辨需依源误差和用途核定，不提前定统一细网格大小或水层阈值。现有岛身份隔离、同源细粗版和异步代次机制保留，具体河槽关键特征保护需新源输入支持。

### 9.1 流式卸载不重置物理状态（设计已确认，数据与实现待验证）

显示块、碰撞块的驻留生命周期与水文控制域分别管理。离屏、进入粗LOD、跨群换锚或卸载近景，不能删除水/盐/沙、暂停独立上游而让下游无来源供水，也不能重载时用初始日指数补满河。世界保存或保有该域的最后完整接受状态、物理时间、源依赖及必要驱动/边界记录。

远域可由同一权威过程以适用粗化或后台方式推进；若以后采用延迟补算，必须从保存的状态沿已有天气和真实边界历程推进，实际外部输入与跨域交换只计一次。驱动或局地分布不足以唯一补算时明确缺项，不用日期差乘平均流量伪造结果。远域近似、补算范围和方法留代码模型阶段，不在本轮规定全行星实时逐格求解。

相邻计算域共享真实界面定位、朝向、对应时段与一份累计交换记录，供体扣、受体加；显示tile和流式岛群边界不自动成为新的封闭水文边界。加载先核对源几何、当前水态及边界时间，再派生显示/碰撞/查询；准备期间不把“尚未加载”呈现成真实干涸，也不从河段ID复制一份旧库存。这补齐第8节相容发布在流式场景中的意义，不提前设计第六层玩家改地。

## 10. 缓存、旧包、存档和重生成：提议的迁移规则

本节只讨论政策，不检查/修改`user://`存档、不清缓存、不重生成、不更换剧情入口。当前格式v1—v5和v8继续按已有读包能力理解；撤回的v6/v7不复用，不能把版本号接近当兼容。

### 10.1 世界事实、水态存档和派生缓存分开

原稿标题“缓存只保存派生结果”不够准确：当前按需生成岛群目录也存有世界的自然事实，不能把它与可丢弃网格缓存混为一类。推荐区分三种内容：**锁定的自然源包/历史事实；运行接受状态和物质库存；可从这些事实重建的派生表示**。存放在名为cache的目录里，不改变其物理责任。自然源包或运行状态缺失时，不能仅凭seed当作一次无影响的缓存清理后重算；只有所需来源、模型、配置、历史/状态充分且相容时才谈重建，否则恢复原备份或明确缺失。

新包清单声明各部分的来源、内容校验、语义能力及依赖。缓存键覆盖世界历史分支、实际几何/水态依赖、配置/模型、坐标时间契约和派生算法版本；只用seed、commit、文件名或mtime不足以识别语义。格式兼容不代表初态、层界和水力模型相容。

建议采用完整包准备、校验、完成标记及相容发布；失败/中断包不进入有效缓存。旧版本缓存隔离保留，可明确回到原世界；派生网格可以在源事实相同条件下重建，不应因此重新产生天气、地形或水库存。剧情包、缓存和按需生成沿当前查找入口，但选择时核对该世界锁定的来源，不能从不同目录拼出“都有文件”的混版包。

### 10.2 按变化性质处理

| 情况 | 提议规则 |
| --- | --- |
| 仅表示/序列化变化，物理事实完全相同 | 可做无损转换或重建派生缓存，核对语义、定位/误差和依赖；不推进时间、不变库存 |
| 缺失必需新能力的旧包 | 维持有明确能力标记的旧世界路径；新功能显示缺失/不可用，不用默认0、对称新槽或伪地下网补齐 |
| 新契约已声明，但文件缺失/损坏/相互不符 | 拒收相应快照并明确原因，保留上一完整版本；不能掉回旧生成公式掩盖破损 |
| 生成模型/材料/几何成因改变 | 视为新世界历史或显式迁移，seed相同不保证世界相同；旧世界继续锁定其原有事实 |
| 决定重生成部分节点 | 明确范围与外部依赖；该节点细版、全部相关LOD、出口/边界、点位和初态一起校核，邻接未变域需相容证据 |
| 新世界或全量重生成 | 单独授权、明确初始历史；不继承旧水态冒充新世界已经演化，不覆盖旧存档 |
| 旧改造/建筑/点位遇新地形 | 记录原来源与实体引用，有明确映射和接触核对才迁移；无法映射列冲突，不强移到最近平地或穿岩；操作细节留第六层 |
| 恢复存档 | 加载被锁定的自然几何/来源、运行变化、唯一物质库存、过程时间和驱动状态；不重新预热，不把当前年份重新套第0年日曲线 |

当前旧包缺少完整R/L/M/G及物质分布，不能从`rivers.tsv v1`恢复准确的新水态：日指数不是水量库存，均值浓度不确定局部盐沙分布。需要依据明确的旧初始历史求相容情景或另建世界，未知保持未知；转换时不会凭空生成“一份准确的新存档”。

### 10.3 存档的最小物理连续性

保存世界身份/历史、自然源引用与所需几何变化、层序/通路状态、各控制体的局地水盐沙归属、接受时刻、历法与过程进度、驱动/随机状态和前身后继记录。体积/水头摘要是否足以重建分布由模型域决定，信息不足不能按容量比例猜分湖水量。

同一接受状态作为恢复边界；不能只存日期和一个径流指数，然后载入时填满所有库。迁移先在副本上给出可审阅的映射、缺失和冲突，核对局地空间/通路/材料、水量与时间，再由用户授权应用；保留原文件与回退路径。这个提议不构成本轮迁移授权。

“保留旧世界”还要求解释能力相容：旧格式读得出，不代表当前模型能继续推进该世界的原水态。需要相容的旧语义/模型与充分输入；如果这些不再可用，明确仅支持历史查看、需要显式转换或无法继续，不能拿新默认参数在旧几何上悄悄重算并声称历史未变。本轮不安装旧程序、恢复旧实验或执行任何转换。
