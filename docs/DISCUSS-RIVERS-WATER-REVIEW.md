## 2. 复核结论：七层共同的五个结构性缺口

七层分别读下来，问题高度一致。原文把"不能怎样简化"写得很充分，却很少回答下面五件事：

1. **表示与"算到哪里为止"。** 原文到处要求"真实、实际、同源、闭合"，但没有规定用什么表示、什么分辨率、哪些离线算、哪些运行时算，也没有"够用"的判据。求解器的选择被推给"后续模型阶段"（第四层第79行、第六层第97行），结果没有哪一层负责。计划第13、79行又要求水量、材料和机械能在每个计算核里都闭合，第66行不先规定格距，第113行唯一的下限是"不模拟逐原子反应"。实现因此一路从固体做到热、孔隙水，再到三维非静水。
2. **最小可交付与用户检查点。** 七层都要求等上游完整成因到齐后才开工，验收只有一张总表。计划的首个游戏端交付排在P06/P07，而总纲第2节的问题和第五层"当前游戏端优先级"本应最先处理。计划第259—261行允许执行者"缩小支持域、继续不受影响工作"，且不必回报，于是没有任何停下来询问用户的条件。
3. **虚构物性没有定值通道。** 浮石、骨架和封存岩层的物性属于世界设定，只能由用户给出，不能实证，也不能倒推。原文要求"成因链有来源"，却没有安排用户定值的步骤，形成链在定值前无法产出任何世界数据。
4. **空岛特有现象没有对象。** 每条自然河的终点都是岛缘：岛缘出口、离岛去向和下方承接，在第二层里一次都没出现，其余各层也只有否定性约束。双时基（一游戏日为2400现实秒，行星自转24小时，物理过程是现实的36倍）、寒季冰盖、淹没对村落的后果，同样各层都缺。
5. **与之后落地的决定没有协调。** 浮高计划 `PLAN-FLOAT.md` F2/F3（按岛龄定高度、截短龙骨）与第一层"不用岛龄直接降低支撑"冲突；运行时天气已有 `WeatherModel`/行星天气场，却未定为唯一来源；10-26选定的「精绘日式三维」晚于第五层；水色简化后，光学介质和初始色类没有来源。

此外各层有若干独立缺口，见第4节。

## 3. 跨层补案

### X1　保真度档、基准表示与"够用"判据

**三档归属。** 七层每条规则标明它属于哪一档：

| 档 | 含义 | 例子 | 交付 |
| --- | --- | --- | --- |
| A 设定约束 | 世界设定的自洽论证，在设计和参数表中论证一次，不做逐步模拟 | 第一代元素来源、成核接合、储能势构成、亿年保存、封存岩层释放机理 | 对快照的检查项：质量、支撑≥重量、力矩、闭合循环不净造功 |
| B 生成期状态 | 生成器离线计算，只把有消费者的量导出（X1与第四层补案） | 岛体顶底与层界、材料、盆地V(z)、出口、河段断面、初始水态与预热 | 导出包字段及其来源哈希 |
| C 运行时状态 | 游戏运行中推进的量 | 固定几何上的水态、改地、用水与载体 | 存档与查询 |

**各域的基准表示。** 基准档就是默认交付档。升档需要书面理由，说明哪一项下游判断在基准档下会出错，并附成本估计和用户批准。

| 域 | 基准表示 | 可登记的升档 | 基准档明确不做 |
| --- | --- | --- | --- |
| 岛体与层序 | 顶面/底面高度场、有限层界栅格，崖线、出口唇、岩溶支路、空洞等用稀疏局部对象表示 | 局部对象不足以表达已登记的通路或崖面 | 四面体实体、应力应变场、热传导、相变动力学 |
| 地质历史 | 离线成熟快照，由简化运动学历史驱动，只核对质量、支撑与力矩；运行时冻结 | 由生成器"临界控制点清单"触发的单点运行时事件 | 运行时地质积分；地质加速进入游玩 |
| 河与渠 | 一维河段网：断面 A(h)/T(h) 与阻力，按适用性用扩散波或动力波 | 玩家改地近域、已登记的汇口或复杂出口：二维深度平均 | 三维非静水、自由面追踪 |
| 湖塘 | 盆地 V(z) 水位—库容，Fill–Spill–Merge 层级，必要的洪泛单元 | 大湖的风生水位差等已登记例外 | 湖内三维环流、温度分层 |
| 出口与岛缘 | 控制断面：自由出流按临界/能量关系，淹没时按上下游水位关系（总纲4.7）；岛缘为自由跌落边界（X4） | — | 离体水三维轨迹参与水量求解（只做显示） |
| 土水 | 少层土桶（根区/下层），入渗容量法 | 堤体等已登记局部需要湿润前缘时 | Richards 方程、毛细能量 |
| 地下水 | 分区水头库或分层准三维（层内二维达西、层间越流） | 已登记岩溶或裂隙通路：一维管道 | 孔隙弹性、水岩共同形变 |
| 冰雪 | 温度指数（度日）积雪/融雪与冰盖状态（X6） | — | 热传导、冰力学 |
| 床岸演变 | 生成期离线事件序列；运行时冻结，只在近域被事件超过起动判据时做降阶更新（第三层补案） | — | 运行时连续床岸演化 |
| 守恒 | 水量、质量与沙量全程闭合；机械能只在控制口、坝堤和取能装置处按水头损失计 | 第七层大型水利耦合 | 每个计算核单独做能量闭合并分配数值耗散的热去向 |

**"够用"判据。** 每个消费者先写出自己要做的判断：干或湿、是否连通、从哪个出口走、控制点水位、身体采样处水深、能否通航。只在登记的样本上，做两档分辨率或两档时间步的对比；判断不变、且该量落在该用途的误差预算内，就算够用。不以"物理上继续收敛"为目标。

**耦合方向。** 默认单向：地质快照或改地发生后，再把原有水量重新分配到新几何上。只有当排水特征时间与形变特征时间可比时，才逐例登记为耦合求解。这个判定是无量纲比较，不预设阈值。

**事务粒度。** 预览、回执、幂等和恢复放在世界发布层（第四层8.2），每个计算核内部不各做一套。

### X2　世界设定定值通道

浮石密度、储能幅度、结构强度、封存岩层的释放速率等虚构物性，由用户给出取值范围，或在几个有说明的选项中选择，然后登记进参数表，并注明"世界设定"。这是选择输入，不是看着河宽倒推参数：定值时不展示、也不参照它对河宽深的影响。

定值之前，各水层使用**冻结岛体快照**作为输入：即当前生成器的地形、层序与岩性，能力标记为"旧成因输入"。等第一层成因链产出同口径的快照后，在同一契约下替换；下游代码和验收项不变，只有来源标记升级。归档 `RIVERS-WATER-PARAMETERS.md` 末段的登记行可改写为给用户的定值问卷。

### X3　能力分级交付、时间盒与回报条件

下表取代原 P00—P12 的串行顺序（第5节给出完整阶梯）。每一级写明本级宣称什么、不宣称什么，并指定固定样本、验收子集和一次用户检查点。

| 级 | 交付 | 用户检查点 |
| --- | --- | --- |
| W0 | 旧包归因与显示还原：不改数据，只去掉显示误读，统一查询和HUD口径 | 同一河段改前改后；回答"源浅还是画浅" |
| W1 | 一条河的同版纵切：从源头到岛缘出口 | 在岸上走一遍，查看水位、湖口和跌水 |
| W2 | 岛群级季节水情与湖塘湿地 | 看同一处一年中的变化 |
| W3 | 玩家改地与用水首切片 | 亲手挖开一道土塞，挑一缸水 |
| W4 | 成因升级：替换"旧成因输入" | 新旧快照下同一纵切的对照 |
| W5 | 按内容需求开启：水面船、取能装置、大型水利、多群推广 | 由对应内容任务确定 |

**回报条件。** 执行中遇到下面任一情况，必须停下，向用户报告并等待，不能自行"缩小支持域后继续"：

- 需要升档；
- 需要一个世界设定值；
- 基准档下某能力无法通过验收；
- 超出时间盒或预算；
- 与已确认设计发生实质冲突。

**时间盒。** 每级开工时由用户给定，例如若干工作日或若干提交。超时仍没有用户可见产出，同样触发回报。"仍待"清单只收录阻塞本级交付的项，其余进入积压，不在本级处理。

### X4　岛缘出口：空岛水系的终点作为一等对象

空岛没有海平面基准，自然河网的终点只有两种：封闭盆地，或岛缘自由跌落。本补案把岛缘出口定为跨层共享对象：

| 方面 | 规定 | 归属 |
| --- | --- | --- |
| 几何 | 出口唇折线引用、唇高程、唇部材料、下游面类型（自由跌落、沿崖跌水、渗出面） | 第一层快照 |
| 水力 | 控制断面：自由出流按临界/能量关系（总纲4.7已确认）；记录每个接受区间的出流体积、瞬时Q，以及由临界水深估算的平均出射速度 | 第二、四层 |
| 水账 | 岛级开放边界"岛缘外排"，不回灌本岛；崖面地下渗出记作地下岛缘外排（总纲4.6） | 第一、二层 |
| 承接 | 按落水轨迹或垂直投影判断：命中下方岛的已声明接收范围，就作为该岛的"外来落水"转账；未命中则离开岛群，与陆地蒸散一样作为行星大气/海的开放边界（总纲第369行） | 第一、四层 |
| 地貌 | 出口唇高程是上游下切的基准面；裂点自唇部后退，限定上游能切多深。唇为硬岩时，上游缓坡宽浅是合理结果（长期保存4.3由第三层承接） | 第三层 |
| 显示 | 由接受的出流驱动，分为水帘、破碎、雾化、没入云海四段，并有远近层级；水帘只显示到云带顶（浮高计划F4），不在海面造溅落 | 第五层 |
| 交互 | 出口近域可查询为危险区；越过岛缘的人或物记为"离岛"去向并留日志；恢复规则与水账分开 | 第七层 |

这样一维或二维水力就能完整处理岛缘，不需要三维非静水。归档中转向三维的那个触发点，由这条补案关闭。

### X5　双时基：世界钟与实时消费者

现状：正常钟速下，一游戏日为2400现实秒（`src/day_clock.h`）；行星自转24小时（`PLAN-PLANET.md` 第29行）。因此1现实秒相当于36世界物理秒，加速钟再乘倍率，暂停为零。

| 类别 | 时基 | 例子 |
| --- | --- | --- |
| 慢过程 | 世界钟（物理秒） | 水位涨落、库存、季节、渗漏、淤积、施工工量（按世界钟工时）、水色前锋与洪峰传播 |
| 快场读取 | 现实秒，读取最近接受状态的瞬时场 | 身体受力、船体阻力、流动纹理、浪花、水声 |

规定如下：

- 快场读取者把接受状态当作准稳态场，不自行推进水量输运。
- 流动纹理按物理流速播放，所以1米/秒的水看起来就是1米/秒。洪峰和水色前锋则按世界钟传播，看起来约快36倍。这是明示的双时基，不算缺陷。
- 水态按固定的现实秒节拍发布，节拍由P00实测预算确定。节拍之间的插值只用于显示，查询和HUD读取接受值。
- 加速钟超出局部水力的子步能力时，近域降为声明的降阶档，并标出能力，不悄悄跳过过程。

### X6　寒季的轻量相态

由现有天气链的气温驱动度日规则：积雪与融雪进入已有的N库，冰盖作为静水和缓流水面上的一种覆盖状态。作用只限四项：

1. 冰下开水面蒸发停止；
2. 冻土降低入渗能力；
3. 冰盖河段增加湿周与阻力，抬高水位，小出口可冻结（逐口登记）；
4. 融雪按度日进入水账。

温暖世界（如6068）整段不启用。游戏端在承载模型出现前，冰盖是受限区域：不能潜入冰下，站立判为未支持，并给出可见提示。破冰是材料操作，移开的冰仍计入N库。冬季取水列为第七层验收情景。不做热传导、冰力学和冰凌。

### X7　淹没包络与受体

第二层在可淹没的岸地上，逐地点输出淹没包络：最高水位、受淹时间占比、最长连续受淹时长，并附统计窗口。这是物理输出，不是危险标签。

第六、七层把现有对象登记为受体：房屋、农田、存货、道路、码头与船台、各村取水点。每个受体有"可用/受淹/受损需修"等简单状态，原因可追溯到具体水态和工程。不设灾害频率，不强制损坏。他村的取水点和田也登记为受体，使玩家工程对下游的影响可以追溯；社会反应延期。

聚落营建器仍只作参考。以后若经用户授权接入，选址按"地形 > 合理 > 风格"读取淹没包络。
