# 河流的数据边界与游戏还原

2026-10-02，根据用户要求复核 skyisle-gen `103fea1` 的 `docs/DATA-GUIDE.md` 第三节、`docs/DESIGN-NOTES.md` 四点五十一/五十二，以及 `core/src/island/rivernet.cpp`。原则：有数据就按数据还原；缺少形态或时间序列时明确保留缺口，不把游戏随机结果当成生成器输出。

## 当前版本：常驻河与临时流水分开

生成器子模块 `aa6468c`（含水文修复 `9accce7`），游戏包 `terrain.bin` v7。逐点 `flow_regime=1` 表示常驻河，`0` 表示可能形成临时流水的路径。常驻河读取所属流域的 `index`；临时路径读取独立的 `event_index`，只受雨水和融雪事件供水，有限汇流窗结束后精确归零。窗口为 `ceil(3×quick_days)` 日，采用衰减三角权重；相邻日值在游戏内线性插值。这是日尺度的汇流近似，不能解读成下雨瞬间有水、停雨瞬间消失。

常驻河的候选掩膜用不含集水核凝结增量的径流识别。增大 `water.core_gain` 增强既有河流的供水，不再扩大这个掩膜，也不改变降雨或汇流路径。临时上游的凝结水留在地下供水账，到常驻河参与出流；每个出口有自己的流域，取消小流域共用全群基流的做法。常驻资格仍是降雨阈值与岩性基流水库的工程近似，尚未逐条求解泉眼和地下水出露位置。

生成器网页点击河线后显示当前日期的宽度、水深、流量、流速、平岸尺度、汇水面积、全年有水天数与供水类型；调日期立即刷新。蓝线表示当日有水，棕线表示当日断流的潜在路径。图上细线为便于选取设有最小像素宽度，实际米数以面板为准。

游戏按同一供水曲线计算 CPU 查询、HUD 和 GPU 水面；零流量时宽深归零、不绘制水面，干河床保留。静态地图用棕线标记临时路径，HUD 区分“临时流水”和“河流”。v7 二进制保存 21 列河点，曲线表前半为常驻供水、后半为同序流域的事件径流；仍可读取 v1–v6。Python 和 C++ 导出路径已逐字节对照一致。

本轮重生成 #6329、#6327 细包、开局 320 km 内的 25 份 500 m 粗版，以及全行星天气。远处 8000 份 2 km 粗版沿用原缓存。地形改造引起的拦水、积水、改道和新临时水路按用户要求留待后续游戏层实现；当前只使用生成器给出的原始地形路径。

## 历史：v6 开局只见河沟的显示修复

用户在开局附近逐月调整世界时间，始终只看到异色河沟。实际复现点在 #6329、流域 12、(34450, -12150)，离出生点约 2.1 km。它是平岸宽 0.62 m 的溪涧，12 个月抽样水宽约 0.214–0.455 m、水深约 0.021–0.068 m。

问题在游戏端：原 0.5 m 地面三角形跨过窄河槽，把浅水面盖住；源数据仍有正流量时，旧 3 cm 水深阈值还会把部分月份整条溪流隐藏；8 cm 的岸边透明渐变又让整条浅溪接近透明。旧 `river_e2e` 只查一个点便提前结束，仍允许“少于两处不通过”，因此出现最浅水深为无穷大却验收通过的漏洞。之前距开局约 39 km 的大河截图无法覆盖这个问题。

`34432c4` 的修复只调整显示与网格采样：近处平岸宽小于 2 m 的河槽细分到 0.125 m，更宽河槽仍按 0.5 m；不同精度接缝与碰撞同步。v6 源正流量保留水面，零流量不绘制；旧包继续使用原阈值。岸边渐变改到毫米量级，浅水仍保留掠射角反光。没有抬高水位、放大河宽或更改逐日流量。

新增的斜向窄河槽回归在修复前 16/16 点被地面盖住，修复后 16/16 点水面高于实际地面三角形。`game/tests/river_opening_render.tscn` 使用 F6 同一 `shift_days(28)` 接口，检查 12 个月的 GPU 日历同步与实际可见水面像素，并输出正常材质截图；诊断材质保留生产水位、裁切和深度测试，仅将通过裁切和深度测试的水面片元标成品红色，避免把河床颜色当成水。12 个月通过，每月开局河段检测到 373–1072 个水面像素。日志与截图在 `build/river-opening-green.log` 和 `build/river-opening-green/`。可复现：`Godot --path game res://tests/river_opening_render.tscn -- --shots=<绝对目录>`，需要 GPU，不能使用 `--headless`。

## 已使用的数据

| 来源 | 游戏用途 |
|---|---|
| `row/col`、`down/join` | 保留全部源点与汇流锚点，在点间作有界 Hermite 平滑；预览绘制、拾取与游戏河床共用这一口径 |
| `level`、`flow_regime` | `level` 表示规模；v7 用独立的供水类型选择曲线，不能仅用河流大小推导干湿 |
| `basin`、336 个逐日 `index/event_index`、`q_mean` | `Q(t)=q_mean×对应曲线(t)`；各流域独立，日值在正午，日间及年末线性过渡 |
| `q_bf`、`w_bf_m`、`d_bf_m` | 平岸以下：`w=w_bf×(Q/q_bf)^0.26`，`d=d_bf×(Q/q_bf)^0.40`；`v=Q/(w×d)`，CPU 查询与水面 shader 同口径 |
| `bed_m`、`surf_m` | 河床原值和生成器标注的平岸水面分别保留；当前水面为 `bed_m+d(t)`，不再按相机距离额外抬高 |
| `fp_left_m/fp_right_m` | 左右分别限制水面范围及河床外的地形剖面，不拿较宽的一侧替代两侧 |
| `ssc_mgl` | 用于水色与吸收；它是年均悬沙浓度，取消“径流大就自动更浑”的额外乘数 |
| `d50_mm/d50`、`slope` | 床质区分泥、砂、砾、粗石/基岩；粒径和比降参与水纹与急流泡沫的表现。材质映射属于视觉表达，不新增砂洲、石块实体或侵蚀量 |
| `planform/confine` | 完整保留并供查询；没有更细的中线、分汊或洲滩几何时，不根据类型标签擅自重画河道 |
| `falls` 的 `kind=0/drop_m` | 河口水帘用源落差，取消统一 150 m 高、14 m 水平抛距；未提供 falls 时不补假瀑布 |
| 逐日气温、负积温 | 延用现有冰情表现；没有冰厚/承载力数据，不提供相应物理判断 |

视觉修正还包括：水纹的移动方向沿河，速度使用当前 `Q/(w×d)`；两岸透明度按局部水深衰减；水帘使用侧向法线，包围盒包含真实落差。近处小于 12 m 的河槽局部细分到 0.5 m，其中小于 2 m 的河槽进一步细分到 0.125 m；同一地形函数供地面、碰撞与块边裙边取样。悬沙吸收系数、色值、波纹与泡沫是显示参数，不是新的水文数据。

## 不能由现有数据解决的部分

1. **常驻供水的局地出处仍是近似。** v7 已导出临时流水的逐日断流时序，但常驻河判定仍未细化到每处泉眼、地下水位交切和河段渗漏；流域日值也不描述分钟级降雨过程。地形改造后的水路变化未实现。
2. **年际水文没有多年的序列。** 当前包只有指定年份的 336 天；游戏按年循环这一年，没有根据下一年的天气猜一个新径流序列。
3. **源字段的平岸基准不完全闭合。** `rivernet.cpp` 的 `surf_m` 取栅格 height；河床由地形阶段假设的 `bf_ratio_channel=5` 下切，`d_bf_m` 则用实际流域年最大/年均比计算。此前 v6 #6329 的 52,459 个点中，41,308 个点的 `bed_m+d_bf_m-surf_m > 0.05 m`，最大约 `0.480 m`；v7 调整了事件水量，未统一这两个基准。因此严格同时满足“按给定床高/水深计算”和“Q≤Qbf 时不高于 height”仍需生成器统一基准。游戏保留原值，查询返回 `source_surface` 和 `bankfull_surface_error_m`。
4. **真正超过平岸的洪水没有完整二维解。** `q_bf` 就是该年日流量最大值，正常日序列基本不超过它；手动调试强制超出时仍使用现有简化漫滩横坡，不能当作生成器给出的淹没图。没有新增泛滥范围、泥沙输运或河道迁移模拟。
5. **源中线仍是 100 m D8 精度。** 2026-10-03 修复接入权威数据时绕过平滑导致的折线回退：预览与游戏均以固定源点的 Hermite 曲线细分，汇流点不移动，宽深、床高和流量沿来源区间插值。没有新增随机曲流、分汊或砂洲。内部 `kind=1/2` 跌水元数据仍保留在 landscape 中，目前没有按缺失的崖面几何补成独立垂直水帘。
6. **远处粗地面可能遮住细溪。** 已移除用“离相机越远水位越高”掩盖问题的做法；现有地形 LOD 对窄溪的剖面仍可能采样不足，不能把该限制伪装成真实水位抬升。

## 岛缘

连续岸线严格沿 `coast_dist_m=0`。源数据也提供大尺度高程、岩性、岩壁，以及部分 `collapse_scarp/natural_arch` 等地貌。游戏继续使用这些明确的数据。

没有更细裂隙、崩落块体、岬角缺口轮廓时，不额外叠随机噪声使岛缘变碎。平滑的源轮廓暂时保留；材质与法线能改善岩面表现，但不能宣称补出了真实的地貌形状。
