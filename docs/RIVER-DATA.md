# 河流的数据边界与游戏还原

2026-10-02，根据用户要求复核 skyisle-gen `103fea1` 的 `docs/DATA-GUIDE.md` 第三节、`docs/DESIGN-NOTES.md` 四点五十一/五十二，以及 `core/src/island/rivernet.cpp`。原则：有数据就按数据还原；缺少形态或时间序列时明确保留缺口，不把游戏随机结果当成生成器输出。

## 开局只见河沟的实际修复

用户在开局附近逐月调整世界时间，始终只看到异色河沟。实际复现点在 #6329、流域 12、(34450, -12150)，离出生点约 2.1 km。它是平岸宽 0.62 m 的溪涧，12 个月抽样水宽约 0.214–0.455 m、水深约 0.021–0.068 m。

问题在游戏端：原 0.5 m 地面三角形跨过窄河槽，把浅水面盖住；源数据仍有正流量时，旧 3 cm 水深阈值还会把部分月份整条溪流隐藏；8 cm 的岸边透明渐变又让整条浅溪接近透明。旧 `river_e2e` 只查一个点便提前结束，仍允许“少于两处不通过”，因此出现最浅水深为无穷大却验收通过的漏洞。之前距开局约 39 km 的大河截图无法覆盖这个问题。

`a401987` 的修复只调整显示与网格采样：近处平岸宽小于 2 m 的河槽细分到 0.125 m，更宽河槽仍按 0.5 m；不同精度接缝与碰撞同步。v6 源正流量保留水面，零流量不绘制；旧包继续使用原阈值。岸边渐变改到毫米量级，浅水仍保留掠射角反光。没有抬高水位、放大河宽或更改逐日流量。

新增的斜向窄河槽回归在修复前 16/16 点被地面盖住，修复后 16/16 点水面高于实际地面三角形。`game/tests/river_opening_render.tscn` 使用 F6 同一 `shift_days(28)` 接口，检查 12 个月的 GPU 日历同步与实际可见水面像素，并输出正常材质截图；诊断材质保留生产水位、裁切和深度测试，仅将通过裁切和深度测试的水面片元标成品红色，避免把河床颜色当成水。12 个月通过，每月开局河段检测到 373–1072 个水面像素。日志与截图在 `build/river-opening-green.log` 和 `build/river-opening-green/`。可复现：`Godot --path game res://tests/river_opening_render.tscn -- --shots=<绝对目录>`，需要 GPU，不能使用 `--headless`。

## 已使用的数据

| 来源 | 游戏用途 |
|---|---|
| `row/col`、`down/join` | 保留中线点位、汇流关系；只细分已有线段，不重新追踪河网或添加曲流 |
| `level` | 保留季节性溪涧 0、小中大河 1–3 标签；标签本身不能推导具体断流日期 |
| `basin`、336 个逐日 `index`、`q_mean` | `Q(t)=q_mean×index(t)`；各流域独立，日值在正午，日间及年末线性过渡 |
| `q_bf`、`w_bf_m`、`d_bf_m` | 平岸以下：`w=w_bf×(Q/q_bf)^0.26`，`d=d_bf×(Q/q_bf)^0.40`；`v=Q/(w×d)`，CPU 查询与水面 shader 同口径 |
| `bed_m`、`surf_m` | 河床原值和生成器标注的平岸水面分别保留；当前水面为 `bed_m+d(t)`，不再按相机距离额外抬高 |
| `fp_left_m/fp_right_m` | 左右分别限制水面范围及河床外的地形剖面，不拿较宽的一侧替代两侧 |
| `ssc_mgl` | 用于水色与吸收；它是年均悬沙浓度，取消“径流大就自动更浑”的额外乘数 |
| `d50_mm/d50`、`slope` | 床质区分泥、砂、砾、粗石/基岩；粒径和比降参与水纹与急流泡沫的表现。材质映射属于视觉表达，不新增砂洲、石块实体或侵蚀量 |
| `planform/confine` | 完整保留并供查询；没有更细的中线、分汊或洲滩几何时，不根据类型标签擅自重画河道 |
| `falls` 的 `kind=0/drop_m` | 河口水帘用源落差，取消统一 150 m 高、14 m 水平抛距；未提供 falls 时不补假瀑布 |
| 逐日气温、负积温 | 延用现有冰情表现；没有冰厚/承载力数据，不提供相应物理判断 |

视觉修正还包括：水纹的移动方向沿河，速度使用当前 `Q/(w×d)`；两岸透明度按局部水深衰减；水帘使用侧向法线，包围盒包含真实落差。近处小于 12 m 的河槽局部细分到 0.5 m，其中小于 2 m 的河槽进一步细分到 0.125 m；同一地形函数供地面、碰撞与块边裙边取样。悬沙吸收系数、色值、波纹与泡沫是显示参数，不是新的水文数据。

## 不能由现有数据解决的部分

1. **季节性溪涧的逐日断流范围未导出。** 上游网页 `skyisle_gen/web/static/island.html` 中有 `aMin` 基流水库显示模型，但 `rivers.json`/游戏包只有流域的总径流指数。游戏没有复制一套天气水库或自行加渗漏阈值。v6 正流量浅溪不再套用旧 3 cm 断流阈值；`river_e2e` 的零径流用例仅验证边界条件。
2. **年际水文没有多年的序列。** 当前包只有指定年份的 336 天；游戏按年循环这一年，没有根据下一年的天气猜一个新径流序列。
3. **源字段的平岸基准不完全闭合。** `rivernet.cpp` 的 `surf_m` 取栅格 height；河床由地形阶段假设的 `bf_ratio_channel=5` 下切，`d_bf_m` 则用实际流域年最大/年均比计算。#6329 的 52,459 个点中，41,308 个点的 `bed_m+d_bf_m-surf_m > 0.05 m`，最大约 `0.480 m`。因此严格同时满足“按给定床高/水深计算”和“Q≤Qbf 时不高于 height”需要生成器统一这两个基准。游戏保留原值，查询返回 `source_surface` 和 `bankfull_surface_error_m`，没有静默移动河床或截断给定水深。
4. **真正超过平岸的洪水没有完整二维解。** `q_bf` 就是该年日流量最大值，正常日序列基本不超过它；手动调试强制超出时仍使用现有简化漫滩横坡，不能当作生成器给出的淹没图。没有新增泛滥范围、泥沙输运或河道迁移模拟。
5. **中线只有 100 m D8 精度。** 长直段与折角仍然存在。规范允许游戏在谷底内补曲流，但本轮按用户“不猜数据”的要求保留原线形；需要上游给出更细中线、分汊拓扑、砂洲边界，才能忠实还原这些形态。内部 `kind=1/2` 跌水元数据仍保留在 landscape 中，目前没有按缺失的崖面几何补成独立垂直水帘。
6. **远处粗地面可能遮住细溪。** 已移除用“离相机越远水位越高”掩盖问题的做法；现有地形 LOD 对窄溪的剖面仍可能采样不足，不能把该限制伪装成真实水位抬升。

## 岛缘

连续岸线严格沿 `coast_dist_m=0`。源数据也提供大尺度高程、岩性、岩壁，以及部分 `collapse_scarp/natural_arch` 等地貌。游戏继续使用这些明确的数据。

没有更细裂隙、崩落块体、岬角缺口轮廓时，不额外叠随机噪声使岛缘变碎。平滑的源轮廓暂时保留；材质与法线能改善岩面表现，但不能宣称补出了真实的地貌形状。

## 验证与复现

- 核心检查 `zhouzhu_core_tests river_contract world_rivers edit_patch`：源河点、逐日插值、质量连续关系 `Q=vwd`、左右漫滩、零源流量、真实瀑布落差和 GPU 属性；以实际地面三角形插值验证偏离网格线的 1 m 河槽在枯水时仍露出水面，同时回归地形编辑。
- 完整核心回归与 `river_e2e/world_features_e2e/world_e2e` 检查地形采样和现有玩法。
- `game/tools/river_data_shots.tscn`：从二进制源河点自动选择缓流河段，读取它的实际流域序列，在同一机位拍该年最枯/最湿两天；截图前直接对源数据断言 Q、宽、深和流速。可运行：`Godot --path game res://tools/river_data_shots.tscn -- --shots=<绝对目录> --clear`。
- 本轮样本：#6329 流域 2，(6750, 13250)。第 52 天指数 0.283：Q=0.3029 m³/s、宽 3.727 m、深 0.217 m、流速 0.375 m/s；第 243 天指数 8.875：Q=9.4998 m³/s、宽 9.130 m、深 0.860 m、流速 1.210 m/s。日号均为从 0 起的源数组下标。
- 画面日志 `build/river-data-visual.log`，图 `build/river-data-shots/`；窗口自动退出，没有调用交互调试器。测试通过不代表中心线、LOD 或缺失水文数据的问题已经解决。
- 首次河流复核曾通过完整核心 1771 项、112 项针对性检查和 3 项 Godot 回归，但没有覆盖开局细溪可见性，不能据此认定渲染验收完成。最新开局修复通过 114 项针对性检查、12 个月 GPU 检查与 `river_e2e/world_e2e/world_features_e2e/earthworks_e2e`；开局 E2E 现在实际检查 25 点，缺水 0 点，最浅 0.035 m。

- 最终完整核心回归：1774 项、0 失败（build/river-opening-core-final.log）。子模块提交后，生成器金标比较使用数据包记录的历史来源标签，仍逐字节比较数值输出；没有重写历史 stamp。
